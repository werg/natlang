# Private teacher append preparation

The owner's policy is to use every admitted, usable source promptly, retain the
entire production recipe and earned state, and protect held data. This preparer
does not choose a curriculum, grant admission, or decide whether a model improved.

1. The operator supplies the model, immutable runtime, admitted registry, ready
   directory and current supervised schedule. Exact readers verify those inputs.
2. Enumerate one finite ready-directory census. Authenticate every package and
   its private export, including explicit transported-receipt custody.
3. Keep the existing train prefix. Admit each new complete graph exactly once;
   prove byte or graph-binding equality for every duplicate and reject conflicts.
4. Verify tokenizer/history behavior, held separation and every existing capacity
   envelope. Preserve larger graphs for a real capacity qualification if needed.
5. Produce future train, CE, memory-request, recipe and seed bindings. Preserve
   optional roles, pending obligations, lineage, prior controls and provenance.
6. Verify unchanged inputs and write a reviewable preparation receipt. A separate
   reviewed compare-and-swap adopts future configuration; the preparer never
   changes live training or claims exposure.

These are crisp mechanisms because hashes, source identity, whole-row equality,
exact split exclusion, geometry and atomic custody require deterministic checks.
The existing shared native readers, CE builder, memory request and recipe loader
remain authoritative for both LFM and Mellum. There is no new model-facing text
or generation policy.
