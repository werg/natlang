# Captured authoring compiler recovery

Policy: preserve original teacher files, inputs, targets, actor and trajectory. A captured compiler rejection is an assigned repair, and becomes usable only after its exact historical failure is reproduced and the unchanged complete executable contract passes the current verifier. Never infer an oracle answer or accept compilation alone.

1. Crisp guard admits only TRAIN captures with complete source groups and declared runs, root done, only files failed, exact null root oracle, and a per-run raw-nl-not-compiled diagnostic. Other failures remain repairs.
2. Crisp historical verifier authenticates the actual original 43e task runtime by its complete existing task inventory, runs unchanged files/spec, and requires exact captured verdict equality. The old runtime is evidence, never current admission authority.
3. Current canonical checkAuthoring independently executes ALL original runs and requires every exact expected result. No model generation or semantic coercion occurs.
4. A derived view changes only authoring/files/oracle accounting. It binds the original raw row and historical runtime. The canonical original-row verifier reconstructs that view on every conversion/admission. Current verifier digests remain custody metadata under the existing exact reconstruction rule.

The historical 43e digest is the concrete original generation epoch, not a general arbitrary-runtime trust input. No prompt or live runtime change is introduced by this verifier.
