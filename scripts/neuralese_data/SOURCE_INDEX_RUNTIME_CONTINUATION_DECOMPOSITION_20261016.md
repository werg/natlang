# Continue validated source indexes into the complete native runtime

Policy: use the complete production trainer promptly, retaining every validated
row and its exposure. Reuse a leaf index only when a reviewed extension preserves
the meaning of all rows accepted by its exact previous validator. New forms need
their own validation. Never interpret this as permission to reuse a capacity
certificate, skip admission, change a split, or widen the older prefix proof.

1. Identify the exact seven-file validator inventory of each running parent
   (LFM14ca and Mellumb50) and the complete canonical64ec destination.
2. Check their exact bytes against the independently reviewed inventories. The
   destination's factored manifest helper is also bound. Unknown bytes fail.
3. Preserve the old leaf indexes' exact source/tokenizer/split/model/role keys,
   row bindings, groups, token counts and metadata, changing only the policy key.
   Use the existing durable index-copy mechanism and conflict checks.
4. Rebuild manifests with the destination loader; preserve source priorities and
   all training/exposure state. Missing source indexes require real validation.
5. Qualify actual target execution/capacity separately before cloud continuation.

The seven-file changes have three purposes. Hashing indexes the existing digest
log without changing file hashes. Native source loading factors manifest assembly
into its shared helper, while the leaf constructor and parser remain unchanged.
Row binding serialization omits the new false import-stop field, preserving old
bindings. The compiler adds explicit per-use gradient stops and internal prefix
support; both default false, and its ordinary positional compilation is preserved.
An old validated source cannot contain the newly accepted stop field: its old
ImportSpan constructor rejected that field. Newly admitted syntax is validated
normally and is not certified by an old cache.

This is an exact, reviewed extension for these parents, not a general source
equivalence prover. Tests compare actual old and new loaders, plans, row metadata,
bindings, ordinary/communication/external-state graphs, nested priorities and held
splits; mutations of every bound file must fail. Crisp code is justified here as
the exact byte verifier and durable-copy mechanism. Scheduling decisions remain
the separately declared training policy.
