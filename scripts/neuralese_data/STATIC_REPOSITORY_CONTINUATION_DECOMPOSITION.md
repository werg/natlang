# Pinned repository files as static continuation data

The owner admits general coding capability data as ordinary teacher-forced text.
Keep each complete upstream file and its honest repository/path header. Its commit,
revision and original row remain provenance. Do not invent an assistant answer,
execution result, tool call, or producer/consumer edge. Existing held repository
components stay held; quality and unresolved source components stay pending.

1. Authenticate the pinned Parquet acquisition and exact source-file bytes.
2. Check each source row's repository/path header and original code-body size and
   SHA against its upstream fields. For original CRLF files this publisher uses
   the original byte size with an LF-normalized digest: verify that exact full
   body transformation, preserve original CRLF text, and record both hashes and
   the digest law. Other mismatches have explicit pending
   accounting, never a repaired or fabricated target. Preserve the source text.
3. Join each row's repository and exact content groups. Use existing protected
   group closure before converting any row, so held/quality/pending membership
   propagates through identical files and repository aliases. This source has no
   newly invented evaluation sample; existing held groups determine test rows.
4. Tokenize complete source text separately for each actual model tokenizer, then
   use existing `text_row_graph` to express static next-token continuation. Its
   suffix starts at zero: all original text is ordinary language-model data,
   with the normal first-token mask. No chat template or new model-facing prompt.
5. Preserve every whole row, including large rows. The existing capacity
   partitioner subsequently decides fitting versus executable pending rows.
   Bind source, tokenizer, protection, converter and complete accounting in an
   immutable receipt. Admission, capacity, recipe adoption and actual exposure
   remain separate steps.

Crisp helpers verify source byte identities, types, source checksums, exact group
closure, token decoding, durable output and accounting. The natural-language
policy above decides source use; these helpers introduce no learned policy or
outside generation service. One source adapter serves both student models.
