# Continue task work across an exact source-registry append

The task policy remains: use every usable admitted TRAIN program, preserve held,
quality and pending protections, and retain exact program identities and source
obligations. Registering additional corpora must not erase completed reference
work or restart a durable catalog whose original source decisions are unchanged.

1. The supervisor supplies an immutable snapshot of the historical registry and
   a bound current registry. This is an instruction to continue the existing work,
   not admission for any newly registered source.
2. A crisp verifier authenticates both byte bindings. Every historical corpus,
   its complete declaration, its order, and every other registry field must be
   unchanged. Only distinct corpus declarations at the end may be added.
3. The caller separately authenticates unchanged extraction rules, program bytes,
   runtime, protection, decision holds and source-review authority. A registry
   append never waives these checks or certifies an existing changed declaration.
4. Persist the resulting exact old/new registry witness alongside the original
   immutable input and execution receipts. Preserve existing reference verdicts;
   generate only missing work under the same runtime and protection contract.
5. Continue source discovery for appended corpora using the normal admission and
   extraction checks. Candidate catalog entries, reference-qualified tasks,
   teacher generations, and training exposure remain distinct claims.

The registry append predicate is exact JSON structure verification and artifact
plumbing, so it is a crisp helper in the existing reference-append mechanism.
It makes no curation decision and introduces no model-facing text or GPU work.

## Retained decision receipt after authorized cache cleanup

A generated decision cache's storage location is bookkeeping, not a new source or
an admission decision. Continue only when the retained receipt is byte-identical,
its output digest agrees, and the bound cleanup plan identifies that exact cache,
output size/digest and retained receipt. Record the deleted/rebuildable status
honestly. Every other typed declaration stays exact, including source files,
admission, splits and policy. New sources still use the separate strict append
verifier. The crisp helper verifies these joins; callers retain their complete
runtime, source, protection and execution guards. This grants no training admission
and does not recreate deleted outputs or rerun reference executions.
