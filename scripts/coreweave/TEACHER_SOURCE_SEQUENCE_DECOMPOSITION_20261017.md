# Consume the declared ready task sequence at teacher batch boundaries

The supervising policy is: exhaust the declared ordered reference-qualified
TRAIN packets instead of repeatedly collecting the same small pilot. Keep the
already selected 140-task batch until its actual source bytes are sealed. Never
change an active batch, infer task success from reference execution, or count
source publication as generation or training exposure.

1. An upstream catalog lists unchanged admitted program variants with exact
   source/row/program hashes. It retains held reasons and identity conflicts.
   The existing reference executor qualifies complete original task programs.
2. The supervisor declares the ordered ready manifest, its protection/hold and
   reference-runtime authority, its anchor batch, and the existing source-config
   path. The mechanism follows that order; it invents no selection priorities.
3. Before the existing guardian launches a new batch, exact verifiers check the
   manifest's append-only prefix, every packet/certificate binding, unchanged
   candidate programs, actual anchor bytes and the previous drained boundary.
   Files may be relocated only through explicitly bound asset mappings.
4. Crisp durability snapshots the old configuration and a publication intent,
   then CAS-replaces the regular next-source config under the existing source
   selection lock. The current batch's files never change. Interrupted commits
   reconcile only the exact old or intended new bytes.
5. A sealed queue plus teacher-source plus source-cases proves a packet started;
   a genuine existing guardian boundary proves it closed. These are separate
   durable receipts. No packet cursor advances merely because config was written.
6. Unavailable packets keep the existing source only when the declared policy
   says retain-current. Such repeats never advance the new-source cursor.
7. A drained batch with unresolved collectors may yield to the next independent
   packet only after the existing completion verifier reproduces its exact
   original accounting and every unresolved queue key has the guardian's
   immutable retry queue and original-to-retry witness. Keep that repair lane
   running separately. Record closed, incomplete and repair debt separately;
   never change the original boundary into a successful completion. A missing
   repair witness, changed sample/source/seed or unassigned global error blocks
   advancement. This is an exact custody verifier, not an acceptance waiver.

This changes task scheduling metadata, not prompts, actor/runtime, external
teacher allocation, sample admission or model arithmetic. Production adoption
requires independent review. Tests use real temporary files, publication
interruption and sealed/boundary receipts; no teacher/model calls are made.

## Per-candidate reference runtime continuation

A supervisor may bind a newly requalified candidate's exact proof SHA to its
actual reference-runtime inventory SHA. Older packets keep their original
runtime binding and proof bytes. The task-serving runtime remains separately
bound. This is exact verifier plumbing, not a choice of task or admission:
current protection, original program bytes, complete scripted verdicts and
ordered lifecycle checks remain mandatory. Unknown or malformed runtime
bindings fail closed. Existing declarations retain their single runtime law.

## Exact future task-context deferral

The supervisor may defer explicitly audited invalid-context future task packets.
Keep the original observed entries and ordinals, current/started work, successful
trajectories and original task facts unchanged. Preserve all unaffected sibling
cases as queued, freshly reference-qualified subsets; append those new packet
identities through the existing ready-sequence continuation when qualified.

The crisp seam checks a SHA-bound supervisor exclusion proof against the exact
observed ready declaration, candidate/prepared/cases bindings, canonical program
IDs/hashes and conserved case counts. It may advance only over a declared packet
with neither a pending selection nor a real started receipt. Each skipped ordinal
gets an immutable pending-debt receipt before durable cursor advancement. It is
not a completed batch, generation admission, training exposure or a family ban.
