# Teacher batch and tranche custody

The existing admission policy remains: retain every exact-success full teacher
trajectory, reject or assign repair explicitly, verify its original task and
current protection, and admit both complete student views. Neither a private
export nor reference qualification grants training admission or exposure.

1. Name a tranche by its actual generation epoch, batch and tranche number.
   This is exact path plumbing. Preserve historical batch-21 names; later
   batches get separate directories and corpus IDs, including tranche zero.
2. Resolve the actual collected packet against the SHA-bound ordered ready
   declaration. Verify its prepared/reference files and exact embedded
   selection, rather than substituting the former 140-task anchor. This is an
   exact verifier; the existing packet/source/oracle verifier still decides
   admission.
3. Carry every already admitted teacher corpus as a deduplication predecessor.
   Require earlier tranches in this batch to have either admitted outputs or
   an exact empty-source rejection proof. This is custody/conservation, not a
   new curation policy. Preserve file order and original tokenizer-specific
   conversion semantics.
4. Existing private recovery, converter, global-protection transition,
   registration and BOTH staging remain the executable mechanisms. Operations
   pass the shared namespace and packet bindings into them. Teacher processes,
   model-facing tasks, queued samples and their seeds are unchanged.
5. If the existing materializer rejects whole trajectories, conserve each
   original action by exact source-row/turn identity across emitted graphs,
   exact duplicates and explicit omissions. Require every missing source row
   to be completely absent from graph targets and completely recorded as repair
   debt; partial missing trajectories fail closed. Keep useful independently
   verified graphs from other rows without claiming the held rows were admitted.
   This is an exact partition verifier, not an approval waiver.

6. Treat a retried collector attempt as a separate exact namespace. Its original
   batch/task/seed/source proof remains authoritative, while private frontiers,
   admission outputs and corpus IDs include the actual positive attempt number.
   Earlier-tranche accounting stays within that attempt; all registered corpora
   still participate in deduplication. This is custody plumbing only: a retry
   never grants source qualification or weakens current protection/quality.

## Evaluation-only quality views

An explicit quality-view name separates a verified evaluation continuation from a new generation attempt. Keep the actual batch, tranche, repair attempt (if any), export archive and recovered raw files unchanged. Only derived admission files and the corpus identity receive the named view suffix. The existing source-quality verifier must reconstruct the view from its original captures; naming grants no admission. All registered predecessor corpora, including the original view, remain in the exact deduplication closure. Original earlier-tranche obligations are retained; a quality view creates no fictional generation attempts.

## Completed source phase custody

A restart resumes a completed source phase by authenticating its exact original
source, transfer, packet, recovered raw captures and executed operator closure.
The supervisor records a durable completion receipt only after the source phase
succeeds. The receipt preserves historical quality-verifier metadata, which a
later runtime rebuild must not rewrite. It is custody, not an admission grant.
The converter and final admission verifier always run again with their current
source/oracle and global protection checks. A missing or changed completion
receipt cannot skip reconstruction. Exact hashing and before/after file-state
checks are crisp mechanisms; the existing quality policy is unchanged.

## Explicit per-model rendering profiles

The source task and exact captured action remain the training obligation. A
student rendering profile changes graph bytes and their IDs, not the original
source-row SHA, source ID or captured turn. This is an exact custody verifier,
not a new quality or source-selection policy.

1. Authenticate each model's conditional explicit profile against its effective
   tokenizer receipt. An omitted profile retains the historical graph-ID law;
   the effective Mellum KEEP default alone does not imply an explicit override.
2. Verify every emitted and deduplicated graph ID using that model's profile,
   retaining exact raw source-row SHA, original source ID and captured turn.
   Source groups, train split, decision holds and complete action partitioning
   keep their existing checks.
3. Compare the original eligible and omitted action identities across models.
   A different rendering can change which action is already represented by an
   exact predecessor, so retain each model's emitted/deduplicated counts rather
   than requiring equal graph IDs. Every original action still belongs to one
   and only one emitted, duplicate or omission partition.
4. The existing operational final validator calls this shared verifier. Its
   private-export, current protection/closure, original source/oracle, output
   bytes and registration checks remain authoritative and unchanged. Defaults
   retain their old graph IDs and exact pairing behavior.
