# Teacher batch and tranche custody

The existing admission policy remains: retain every exact-success full teacher
trajectory, reject or assign repair explicitly, verify its original task and
current protection, and admit both complete student views. Neither a private
export nor reference qualification grants training admission or exposure.

1. Name a tranche by its actual generation epoch, batch and tranche number.
   This is exact path plumbing. Preserve historical batch-21 names; later
   batches get separate directories and corpus IDs, including tranche zero.
2. Resolve the actual collected packet against the SHA-bound ordered ready
   declaration. Verify its prepared/reference files and exact embedded
   selection, rather than substituting the former 140-task anchor. This is an
   exact verifier; the existing packet/source/oracle verifier still decides
   admission.
3. Carry every already admitted teacher corpus as a deduplication predecessor.
   Require earlier tranches in this batch to have either admitted outputs or
   an exact empty-source rejection proof. This is custody/conservation, not a
   new curation policy. Preserve file order and original tokenizer-specific
   conversion semantics.
4. Existing private recovery, converter, global-protection transition,
   registration and BOTH staging remain the executable mechanisms. Operations
   pass the shared namespace and packet bindings into them. Teacher processes,
   model-facing tasks, queued samples and their seeds are unchanged.
5. If the existing materializer rejects whole trajectories, conserve each
   original action by exact source-row/turn identity across emitted graphs,
   exact duplicates and explicit omissions. Require every missing source row
   to be completely absent from graph targets and completely recorded as repair
   debt; partial missing trajectories fail closed. Keep useful independently
   verified graphs from other rows without claiming the held rows were admitted.
   This is an exact partition verifier, not an approval waiver.

6. Treat a retried collector attempt as a separate exact namespace. Its original
   batch/task/seed/source proof remains authoritative, while private frontiers,
   admission outputs and corpus IDs include the actual positive attempt number.
   Earlier-tranche accounting stays within that attempt; all registered corpora
   still participate in deduplication. This is custody plumbing only: a retry
   never grants source qualification or weakens current protection/quality.
