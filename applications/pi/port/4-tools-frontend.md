# Group 4 — tools, execution environment, coding-agent frontend (pi-durable at f10993b)

Overall split used in this group (applies to every table below):

- **Tool execute functions are fns.** Each of `read`, `write`, `edit`, `bash` (and the frontend's `subagent`) is one natlang
  function whose typed contract is the tool's parameters → `ToolExecutionResult` (`content`, `isError`, `details`,
  `diagnostics`). Each is a unit the tool round records, validates and retries on its own (spec §7.3, §8.4). The fn's
  instructions hold the sequencing, the checks, the attempt rules and the exact model-visible messages.
- **All exact text/byte/line arithmetic is crisp**, in the tools' shared crisp library: truncation, UTF-8 sizes, line
  selection, path variants, edit matching, diffs, image sniffing. The small model never counts bytes or lines.
- **Tool declarations (name, description, parameter schema) are crisp data**, registered verbatim. They are
  model-visible, and spec §7.4 compares declarations at every request: any variation appends a `pi.system` delta and
  breaks provider prompt caches, so they must be byte-stable.
- **ExecutionEnv is a service** (file system + shell). Streaming output, spill files, process kill, timeouts, the
  per-file mutation lock and abort checks all stay in the host; fns see only returned records.
- **The system prompt is crisp rendering**, not natural language: spec §7.4 requires deterministic renderers ("any
  change in rendered text ... appends a system delta and invalidates provider prompt caches").
- **The frontend's TUI and view model are out.** Its bootstrap, session directories and environments are services. Its
  registry/settings composition is crisp data. Its only harness logic is the `subagent` tool (fn).

Tool results pass through the harness's tool task (`durable/src/harness/tool.ts`, another group), which matters for
what the model sees from these tools. When `execute` omits `content`, the retained output becomes the content. Default
`outputLimits` are 51,200 bytes, 2,000 lines, `retain: "head"`. Retained text has control characters other than tab and
newline removed (regex `[\x00-\x08\x0b-\x1f￹-￻]`). A throw from `execute` becomes `isError: true` with an
`error` diagnostic of code `tool_error` and the error message. Diagnostics are ordered: those from `api.diagnostic()`,
then the result's own, then the harness's (e.g. `[warn] Output truncated to its end: N lines, M bytes dropped`). They
are appended to the content as one text item `<harness>\n[severity] message\n...\n</harness>`.

## Summary of decisions (rows above)

121 table rows in total.

- fn: 5 — the execute functions of `read`, `write`, `edit`, `bash` and `subagent`.
- inline: 8 — requireEnv, resolveToolPath, validateEditInput, editAccessError, validateTimeout, prepareExecution, bash
  outcome mapping, answerText.
- crisp: 59 — the 5 tool declarations; all of edit-diff, truncate and image; read's selection, head and slice helpers;
  prepareEditArguments; the decode helpers; the env result/error records; CodingTools; the frontend's settings,
  registry and thinking/model rules; all prompt rendering; ensureChildConversation.
- service: 37 — the ExecutionEnv interface and NodeExecutionEnv, LineScanner, StreamDecoder, node-watch; the
  file-mutation lock; bash exec/streaming and the prepare hook; the frontend's bootstrap, close, submit, compact and
  abort calls, HTTP setup, ExecutionEnvs, initial model choice, prompt resource loading and selectSession.
- out: 11 — re-exports, powershell, main.ts (2 rows), the view model and its helpers, listeners and notices, the command
  queue, toggleTasks/switchConversation, tui.ts. The README has no code units.
- split: 1 — resolveReadToolPath: crisp `readPathVariants`, plus an inline existence probe in fn `read`.

Owner decisions needed:

1. **Deterministic tools as fns or crisp.** `read`/`write`/`bash` are almost pure orchestration of crisp helpers and
   env calls. As fns they cost one small-model invocation per tool call. Alternative: crisp tools called directly by
   the natlang tool-execution fn, keeping only `edit` (or none) as an fn.
2. **Crisp helpers holding a service handle.** `readTextSelection`, `readHead` and image sniffing pull bytes from an open
   `BinaryReader` incrementally. Either allow crisp helpers to take a passed-in reader capability, or add a host
   operation (e.g. `env.readLineSelection(path, offset, limit, maxBytes, maxLines)`) that returns the head and totals.
3. **System prompt text.** Keep pi's text verbatim, or adapt it for natlang? It says "operating inside pi", lists pi
   docs paths, and claims `PI_*` environment variables that durable's bash does not set (no `prepare` hook).
4. **Compaction settings.** The frontend reads `getCompactionSettings()` without a model, so per-model
   `compaction.modelOverrides` are ignored. Port as is, or honour the overrides?
5. **Optional pieces.** `powershell` (out), file watching (`watch`/node-watch: unused; context files and skills load once
   per cwd per process), image refusal in `read` (keep?), spill temp files (never cleaned up).
