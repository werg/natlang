# Selected execution integration decomposition

The callable-folder program remains the application. Natural-language functions,
TypeScript functions, captured values and declared services keep their existing
Natlang interfaces. The selected executor implements their JavaScript semantics
through the common semantic execution contract.

The following components are exact mechanisms rather than application policy:

| Component | Responsibility | Why crisp code is required |
| --- | --- | --- |
| Evaluator installation | Validate authority, preserve `EvalFailure`, cancel and close once | Exact interface and lifecycle enforcement |
| Async module loader | Compile immutable sources, initialize dependencies, preserve live exports and task ownership | Module identity, cycles and cache consistency |
| Binding bridge | Publish declared callable/cell handles, marshal owned graphs, correlate selected actions with observed results | Capability identity and no hidden execution |
| Retained exports | Route every call through the selected driver and preserve owned reference identity | Selected state is authoritative |
| Event ingress | Admit typed events, serialize Fold and bound ordered Map work | Queue order, backpressure, cursor and cancellation enforcement |
| Verification | Compare controlled selected execution with independent results and effects | Reproducible engineering evidence without training |

Changing an evaluator authority invalidates outstanding module references. A task
must finish or restart explicitly; a stale reference never silently executes in
the replacement authority. A module initialization failure remains a failure,
and the loader does not retry native guest execution.

Validation uses controlled semantic selections through the production interfaces.
Those fixtures are engineering checks, not learned-model success or training data
generated by an external model. Training remains outside this implementation task.
