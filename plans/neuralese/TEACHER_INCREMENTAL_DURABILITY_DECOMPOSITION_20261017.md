# Teacher rollout durability decomposition (2026-10-17)

1. **Choose an export tranche** — natural-language policy: retain every finished result in queue order, export at 32 newly finished outputs or after the configured journal-idle interval, never relabel a repair or unstarted row as finished. Crisp helper: joins exact queue keys to terminal `finish` journal entries and rejects duplicate/foreign identities.
2. **Bind and package the tranche** — natural-language policy: preserve the teacher source, exact queue and control/repair snapshot alongside each raw trajectory. Crisp helper: checks output-accounting completion, output manifest source/range, hashes each full raw result and manifest, writes a durable immutable archive and tranche manifest.
3. **Persist privately** — natural-language policy: local raw results are reclaimable only after independent private-object verification. Crisp helper: invoke the existing owner-host single-file private exporter, bind its independently verified byte count/SHA to the tranche, atomically advance the durable frontier, then prune the external-volume raw/tar duplicates while keeping the compact member manifest and receipt. A later poll repairs a crash between frontier commit and pruning.
4. **Close the batch** — natural-language policy: a batch boundary is not complete until every terminal output and final accounting/repair state is durable. Crisp helper: export the final boundary snapshot and verify that tranche keys plus outstanding repair/unstarted keys partition the exact original queue.

5. **Follow the live teacher** — natural-language policy: follow only the active batch whose source and serving identity are currently armed; a new boot or changed identity requires a freshly bound config, while network/read failures are retried and recorded. Crisp helper: owner-host continuous poller reloads the active config every cycle and checks sandbox boot ID, exact source packet SHA, actor SHA, execution-identity SHA, teacher-config SHA and runtime path before reading queue/journal/output files. Its durable poll record keeps active config and error state; its spool must be on the external volume.

The sandbox never receives W&B credentials. Availability and private durability do not grant training admission or exposure. Live adoption still requires a dry-run on real collector output manifests/journal/source/control bytes followed by the existing exporter's private full-object GET proof; retained V21 harvested data does not contain the original collector queue/journal files needed to substitute for that first real dry-run.
