# Neuralese text readout boundary audit — 2026-10-08

## Change

`TEXT_NEURALESE_EMULATION_PROMPT` revision 9 now describes the shared compiler contract: JavaScript text-coercion contexts read a `Neuralese<T>` operand at its declared type, then continue with native JavaScript conversion. The prompt names `String`, untagged template interpolation, string concatenation, `Error(message)`, `JSON.stringify(value)`, and supported native text methods. It also says this does not enable opaque field inspection or turn console display into readout. This repairs a prompt/code mismatch: the prior prompt said no general text conversion applied to other `Neuralese<T>` types, while the compiler already lowers explicit `String`, template, concat, `Error`, JSON, and declared text-method contexts through typed readout (`ts-host/src/compiler/neuralese.ts`, especially lines 360–415).

This wording change is a prospective ergonomics correction. The examined traces do not establish that the previous sentence caused a conversion failure.

## Deliberate boundaries

- `String(Neuralese<Record>)` reads the declared record and then follows native JavaScript string conversion. It does not silently become JSON serialization.
- `JSON.stringify` remains a separate explicit native operation; only its actual typed-readout operand is materialized.
- Console display, arbitrary marker-looking strings, and wrapped `return_result` strings do not create typed reads or semantic writer evidence.
- The single observed bad `natlang.read` string has no detectable representation error: the model returned a string of the declared type. Improving it requires readout-quality evidence or a future qualified retry design, not a sanitizer that guesses content.

## Follow-up boundary review — JSON containers and array coercion

This review checked compiler behavior and generated V24–V26 eval actions. It found no historical generation attempt that rejects or mishandles nested-soft JSON serialization, `String(array)`, or template interpolation of an array containing soft values. Treat the cases below as prospective ergonomics findings, not observed generation causes.

- `JSON.stringify(softValue)` is already typed-readout aware for the complete first argument, including crisp/soft unions. The compiler captures the native JSON receiver, method, and all arguments before awaiting that read; tests cover module/eval lowering, assignment and `typeof`, nested direct JSON calls, crisp and mixed arms, replacer/space side-effect order, and propagated read failure (`ts-host/src/compiler/neuralese.ts:384–390`; `ts-host/src/compiler/lower.ts:190–209`; `ts-host/test/neuralese.test.mjs:600–728`).
- `JSON.stringify({ notes })` where `notes: Neuralese<string>` does not read the property. The root argument is a crisp record, so native JSON serializes the ordinary reference form (`{ "$neuralese": { type, id } }`; `ts-host/src/native/neuralese.ts:14–39`). There is no matching V24–V26 generated attempt in the inspected traces. Automatically reading nested values would require an async prewalk or clone, which can change getter/proxy timing, `toJSON`, replacer calls, cycles, and key traversal. Keep the explicit distinction: for a known field, use `JSON.stringify({ notes: await read(notes) })` with `read` from `natlang:neuralese`; for a whole typed record, read the `Neuralese<Record>` operand itself. Do not silently recurse through arbitrary JSON graphs.
- `Array#join` already handles a declared array or tuple with direct Neuralese element alternatives, including mixed crisp/soft arrays and a soft separator. The native join path preserves custom `join` dispatch and argument evaluation, then reads direct elements in order; tests also cover length conversion, holes, inherited indexed properties, getter failures, and custom thenable results (`ts-host/src/compiler/neuralese.ts:129–155,402–405`; `ts-host/test/neuralese.test.mjs:746–799,828–955`). No rejected or incorrect V24–V26 generated `join` attempt was found.
- `Array#toString()` has its own typed path for arrays with direct soft elements. It preserves the native method lookup and custom `join` behavior, and intentionally does not recursively read nested arrays (`ts-host/src/compiler/neuralese.ts:152–155`; `ts-host/test/neuralese.test.mjs:1120–1179`). In contrast, `String(values)` and `` `${values}` `` are not recognized from the array element type: direct String/template readout checks only whether the expression itself has a soft alternative (`ts-host/src/compiler/neuralese.ts:354–356,369–373`). No such attempt was found in the inspected generation actions. For ordinary arrays, `values.join()` is the transparent existing spelling when comma-joined element text is intended. General support would need async-aware `ToPrimitive` handling that honors `Symbol.toPrimitive`, custom `toString`/`valueOf`, and native method lookup without changing custom-return or thenable behavior; leave it deferred pending a separately specified helper contract and an actual use case.
- Soft `JSON.stringify` replacer/space options currently produce an opaque-value diagnostic (`ts-host/src/compiler/neuralese.ts:386–389`). No matching V24–V26 attempt was found. These arguments have distinct native callback/formatting roles, so the direct first-operand rule does not imply that they should be read or converted automatically.
