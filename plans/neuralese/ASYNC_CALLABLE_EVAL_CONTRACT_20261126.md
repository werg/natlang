# Asynchronous callable result fields

An original wave83 Launch invocation read its exact active Native snapshot but returned null: the model wrote `const snapshot = readSlot(...)` without `await`, then compared `snapshot.panelId`. Its source callback header declared `Promise<LaunchSnapshot | null>`. The semantic callback type intentionally normalizes Promise away (`ts-host/src/native/types.ts:244`); the actual checked typed-slot wrapper is asynchronous (`native/values.ts:367`). The original requested trial/note remain absent; this source fix does not promote that old outcome.

The common eval ambient scope already restores Promise through `compiler/eval-check.ts:typeScriptText/scopeDeclarations`. However, `checkEvalFields` excluded receivers whose type was declared outside the virtual scope file. Standard-library Promise therefore escaped the pre-effect field guard. The shared checker now rejects nonexistent property and literal-index reads on a checker-known awaitable before executing the snippet. Actual Promise members remain legal. Runtime option `checkAwaitedFields:false` preserves the previous behavior for controlled comparison. Ordinary synchronous local functions and their returned records remain synchronous.

The common model opening (`native/agent.ts:inputsListing/callHeading/scopeReading/referencedTypeAliases`) now uses the existing TypeScript callable renderer for semantic typed arguments and aliases. Semantic Type parsing, normalization, serialization and occurrence/capture identities retain their existing format. Explicit synchronous TypeScript module declarations are unchanged.

Mechanism inventory: Node and Workerd interpreter invocations share `runtime/kernel.ts:877` and `runtime/hooks.ts:24,51`; standalone NodeNativeRuntime defaults to the same hooks (`node-runtime.ts:54`). The browser and all five generated SDK targets bundle that same compiler/native code. Managed llama, Pi and in-page wllama supply model turns to the common NativeAgent; they do not implement a separate JavaScript callback type checker. Python native and SGLang servers are inference backends (the engine table in `docs/ENGINE_PARITY.md`), not JavaScript evaluators; no server protocol or sampling law changes. Hosts that explicitly supply custom NativeRuntime hooks own their replacement checker. Learner and Python/Node trajectory readers consume existing captures and require no schema change.

Validation: ledger `natlang-async-callable-eval-contract-20261126a` actually ran official build:node and build:core, then 26 controls passed (11 new plus existing field/binding controls), 50.6s, 1.3GiB peak. Node and Workerd each prove missing-await field access is rejected with zero callback effects, awaited exact Native values survive, synchronous local callbacks stay normal, and the explicit opt-out performs the old callback effect. Model openings on both platforms advertise Promise-returning callbacks. Semantic Promise-normalization equality and property/literal-index/then controls pass. No network/model calls, Source51 mutation or historical raw rewrite.

Lexical-capture generalization is checked, not guessed: compiler/targets.ts:182–211 converts only Promise-like function targets to semantic lambdas; synchronous JavaScript callbacks remain Live function identities. Four additional actual Node/Workerd controls preserve ordinary synchronous captures and reject missing-await access on asynchronous captures. No new capture metadata or semantic codec change was necessary.
