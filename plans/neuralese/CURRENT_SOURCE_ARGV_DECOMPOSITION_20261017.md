# Current source arguments at continuation boundaries

The recipe decides which whole sources a stage trains. A continuation must use its actual resolved stage inputs after resident adoption, while retaining the saved parent, per-row credits, optimizer and RNG.

1. Resolve the current recipe stage with the existing authenticated input resolver.
2. Replace source-role arguments in the existing shared trainer command from those resolved inputs. Remove obsolete literal, duplicate and equals-form arguments; reject incomplete arguments. Preserve custom launcher contracts and unrelated arguments.
3. Emit exactly one declared argument per current role, including the actual continued predecessor. Absent optional roles remain absent. Keep objective binding in the existing objective verifier.
4. Verify a real resident adoption followed by command construction uses the adopted source and predecessor, without changing prior saved state or inventing visits.

This is crisp argument serialization and verification, not a second scheduling policy or a new training path. Both models use the same helper.

A qualified capacity identity may predate explicit IEEE attention metadata. The shared geometry identity verifier compares an omitted mode as IEEE, preserving certificate bytes and every other model/runtime/packing field. The same comparison protects inherited capacity evidence; actual different modes, nulls and altered fields still fail. This does not hot-patch a frozen worker: adoption happens through the next explicit qualified continuation.
