# Vibe Studio semantic-function cutover

The complete corpus now uses ordinary application functions in the shared hierarchical Natlang codebase. The task supplies its declared entry and typed inputs; it does not prescribe the teacher’s child-call sequence. A result is application data. Native calls, effects, model exchanges and source identities supply execution evidence.

## Six migration steps

1. Inventory: shared router, authored runner, services, all outcome binders, exporter, Python loader, independent JS verifier and native TS materializer are mapped in `VIBESTUDIO_SEMANTIC_FUNCTIONS_DECOMPOSITION.md`. Obsolete unregistered exporter checkers were removed after checking actual registration; historical capture support retains original identities.
2. Application library: domain and composite entries have native typed arguments/results and hierarchical specialist lambdas colocated with exact TypeScript helpers. Installed skills provide contextual knowledge where appropriate. The collection entry is no longer `runUserGoal`.
3. Whole-corpus binding: every existing task resolves to its declared application entry. Complete catalog identity comparison protects all original goals and splits.
4. Outcome checks: remove incidental discovery counts, method order, reread restrictions, dummy observations and mandatory generic reports. Keep user-requested answers/order, source bytes, actual state, scope protection, approval and revision/CAS constraints. The System Testing audit classifies 116 entry kinds and 128 shape candidates against source and user goals; it does not equate every count with a defect.
5. Recover data: additive reassessments preserve original failed packets and source identities. Fourteen recovered trajectories contain 105 supported decisions: two completed goals/40 decisions and twelve partial trajectories/65 decisions. Wrong optional root conclusions remain observations with zero target weight. Existing Sol captures and all failed raw captures are retained; new teacher generation uses Luna only.
6. Pipeline: actual native trajectory IR enters registry-backed export and student reasoning fill before SFT. Observed graph telemetry reports actual depth, branching, functions, edges and namespace composition separately for completed, partial and preserved failed captures; it is not an admission gate. Collection uses a shared prepared Vibe Studio instance with eight workers, a 16 GiB cap and 7.5 GiB Tick reserve. The Android-only tail owns one disposable emulator after bulk collection. DGX jobs preserve 15 GiB ledger headroom; existing training is not stopped.

## Durability and validation

Core persists running call checkpoints and native value bytes in Node, portable SQLite/WASM and real browser OPFS stores. Browser writes acknowledge only after commit. Base journals each exact provider exchange and owns capture state per attachment, drains in-flight replies on teardown, retains failed writes, and fences the actual resolved teacher model before inference and scoring. Failed normalization retains original gateway replies. Capture-required persistence errors remain errors.

Host ABI 3 provides a private native SQLite emergency sink bound to the actual owner, run and provider execution. Shared runtime retirement streams and verifies it into `state/capture-evidence/natlang/<entityHash>/<payloadSha>` before completing cleanup. A failed archive keeps native SQL and marks cleanup incomplete for the existing reaper while still joining process cleanup. Managed state lives outside disposable ownership scratch. The collector moves the entire retained generation into the capture tree even when no CLI run ID was obtained; checksum-verified whole-tree DGX transfer precedes local capture deletion. If stop/move fails, the original local state stays durable rather than being claimed as remotely archived.
