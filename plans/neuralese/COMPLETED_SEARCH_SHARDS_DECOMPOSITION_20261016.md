# Admit completed Search/OWL shards continuously

The supervisor admits useful completed source shards while the remaining
renderer jobs continue. Whole source coverage remains mandatory; a partial
shard frontier is never full-source completion or earned training exposure.

1. Read the existing complete selection and exact launch binding. Discover
   shards with both current renderer receipts; legacy filename-only markers
   do not qualify. Skip already registered shard identities.
2. Reuse the renderer's exact trajectory/aggregate verifier, reconstructing its
   existing input binding from the declared tokenizers, pieces and protection.
3. Reuse the static native text converter for both views and models. Resolve
   input file symlinks before invoking its older decompression wrapper.
4. Parse every output with NativeGraphSource; verify current connected held,
   quality and pending protection, source decision holds, counts, splits and
   view identities. Preserve complete source and renderer provenance.
5. Publish immutable corpus manifests with the existing registry publisher.
   Cloud staging, capacity admission and actual trained exposure are subsequent
   explicit operations. Repeat as more durable renderer shards finish.

Selection/admission policy is stated above; Python supplies exact verifiers,
durability, subprocess invocation and the existing registry plumbing. No
semantic graph edges or teacher correctness are inferred from static text.
