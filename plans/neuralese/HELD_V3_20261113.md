## Construction

Same rules as held-v2 (`held_eval pin`, pool b3fef4c7, seed `held-eval-20261110`, family/level stratified, a third
effect-state), from `ops/held-v3/pin.sh`:
`pin --include-manifest held-v2/manifest.json --replace-ids held-v3/replace-ids.jsonl --reject-ids held-v3/reject-ids.jsonl
--avoid-ids held-v3/exposure/exposure-ids.json --avoid-groups held-v3/exposure/exposure-groups.json
--avoid-from bf95-lowlr-1105/w5 --also-exclude held-v2/manifest.json`.

New `pin` options (`rl/held_eval.py`):
- `--replace-ids`: drop these included tasks. Each gets a fresh task of its selector family and level. It prefers the
  same effect-state class and source family, then the nearest level, and falls back to the stratified fill.
- `--reject-ids`: rows never chosen (pool errata, reviewed bad candidates). Their split groups stay eligible.
- `--avoid-groups`: split/source group names of exposed rows outside the pool. Candidates are now also refused when a
  *source group* (not just the split group) is shared with exposure. This is the closure `grpo.load_tasks` already
  applies to training.
- `--also-exclude`: an earlier manifest. `exclusion_ids()` follows `also_excludes`, so held-v3's exclusion contains all
  of held-v2's (1,170 of the 1,204 ids). Training on v3 therefore never takes a v2 held task or sibling.
- `held_eval verify --manifest M --avoid-ids/--avoid-groups/--avoid-from`: held tasks whose id or split/source group
  overlaps exposure. Exits 1 on any overlap.

Result: 256 tasks, 242 kept from v2, 14 replaced. Levels 63/64/64/65, 91 families, 85 effect-state (as in v2).

## Scorer changes (enter at the boundary; new series)

These change every comparison. Held-v3 results are a new series: compare only with results on the same pin.
- **Extractive QA cores** (`oracles.ts qaAnswerCores`, verdict `qa-span-core/1`). A span-QA answer that fails F1 is
  scored again on its core. The core drops a leading possessor (`X's`, `X Y's`, `my/his/their ...`), then the longest
  leading run of words that occurs contiguously in the task's `question` input and holds no gold word. A core that
  hedges (or/and/not/maybe ... absent from the gold) is never offered. Fixed: "the alien's spaceship" / "The
  spaceship", "just had sex" / "Sex". Still rejected: "Duke Lemur Center" / "Duke", "sex or coffee", "did not have
  sex", "14 surgeries" / "14".
- **Terminal newline** (`FilesOracle.terminal_newline`, collector `withTerminalNewlinePolicy`). `content` compares
  accept one missing or extra terminal LF/CRLF on non-JSON files. This applies only when none of the task's `.nl`
  instructions mention a newline, line break or line ending; otherwise the compare stays byte-exact. Fixed: row 53/0
  (rejected.md). desk-requests-thu-1105-a ("then a final newline") stays exact.
- **Loop evidence equivalent to iterateOn** (runtime option `traceStepStates`, collector `loopShowsIterationMarker`).
  The option is set only for cases whose decisive marker is an iterateOn step marker (`"phase":"step",...,
  "state_hash"`: 7 pool rows, all `iterate_schedule_repair`). With it, each call of a program TypeScript function
  records the `stableHash` of its result as a `step_state` trace event (no graph node). The marker also counts as
  observed when the run's own calls produced the marked state at least twice, i.e. a bounded loop over the real step
  function saw the cycle. Fixed: row 30/1. A loop that stops before the state recurs still fails.
- Versions: `answer_comparison_version` normalized-decimal-exact/4, `file_content_comparison_version` json-content/3.
  These are trajectory reuse keys.

Check: all 512 base episodes (grpo-v1 run2 `held/step-00000`) re-scored for answers (399) and content files (131). Only
the four intended verdicts flip (23/1, 52/0, 52/1, 53/0). Row 30/1 is covered by the replay test.
Tests: `ts-host/test/oracle.test.mjs`, `blocked-stop-evidence.test.mjs`, `tests/neuralese/test_rl_curriculum.py`.

## Training exclusion switch

- `grpo.py` (and `exp1_measure_cases.py` / `neuralese_variants.py` through `grpo.HELD`) now defaults to held-v3. Its
  exclusion includes held-v2's ids and siblings through `also_excludes`, and the source-group closure in `load_tasks`
  applies to both. `--held-manifest .../held-v2/manifest.json` restores v2.
- `lower_sft_sources.py`: pass `--held-ids held-v3/exclusion-ids.json` (it contains v2's) and `--held-cases` for both
  `held-v2/cases.jsonl` and `held-v3/cases.jsonl`.
- The v2 ignore lists are not needed on v3. Its wrong-oracle tasks are gone, and the ENOENT tasks are scorable since
  e9a7360cc.
