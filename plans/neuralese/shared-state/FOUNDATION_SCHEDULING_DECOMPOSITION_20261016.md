# Complete the declared communication foundation promptly

The supervisor's production policy is to finish the original declared genuine communication cohort before newly appended communication can postpone shared semantic training. All ordinary and expanded-source row quotas remain mandatory. While a fixed-foundation deficit exists, use up to four foundation communication batches per explicitly prioritized ordinary batch. Priority-positive communication and ordinary data should start promptly, while priority-zero ordinary debt must continue to receive a bounded share even as new reviewed data arrives: when both lanes are pending, schedule four communication/priority batches for each priority-zero ordinary batch. Derive the starting position from the saved optimizer step so a stop, append, and resume cannot restart every continuation at the fast lane. This preserves roughly 64% foundation, 16% new-priority, and 20% old ordinary updates while the fixed foundation and priority lanes are both full. This is a training curriculum change, not a qualification relaxation or a change to graph loss.

The natural-language stage is: (1) identify unvisited rows of the exact declared foundation using existing authenticated row IDs and saved exposure; (2) place batches containing those rows ahead of other communication batches, retaining packing and order inside each category; (3) interleave up to the declared number of foundation communication batches with one priority-positive batch; (4) merge that prompt-progress stream with priority-zero ordinary debt at a four-to-one rate, using the durable optimizer step as the cycle offset; (5) when any lane empties, continue the other lanes without dropping or replaying a row. The existing foundation readiness gate remains unchanged and starts the actual shared recipe only after both participants qualify.

Crisp mechanisms implement exact source membership, deterministic ordering, quota accounting and resumable iterators. The monotone source reader includes foundation membership in its existing per-visit/rank stream key, so moving a foundation batch never reverses a decompression cursor. No new random draw, optimizer, exposure store, parser or trainer exists. A resumed or resident-appended source rebuilds the same schedule from actual saved counts; consumed rows never replay. The opt-in recipe parameter `foundation_communication_batches` declares the ratio and requires an exact foundation source. Omission preserves existing scheduling.

Validation covers old-default identity, rank/packing preservation, fixed-cohort priority despite expanded high priorities, four-to-one foundation ordering, bounded service to priority-zero debt under repeated append/resume, zero-class cases, exact monotone source reads and an actual tiny trainer continuation. Production adoption requires independent review and the ordinary safe runtime handoff; no live trainer overlay.
