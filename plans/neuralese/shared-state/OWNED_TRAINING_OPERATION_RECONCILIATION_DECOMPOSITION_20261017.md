# Reconcile completed owned training into the existing recipe scheduler

The natlang policy is: preserve every earned update and outstanding obligation,
acknowledge the actual completed finite operations, then continue the existing
recipe scheduler from the actual latest full optimizer. An operator chooses the
safe boundary; a finite quantum never means that its whole stage is complete.

1. Name the original controller bootstrap, current cursor/state/config and the
   actual ordered owned operations. Keep original bytes as immutable evidence.
2. Authenticate each operation's exact parent, source recipe and lineage,
   supervisor launch/argv/identity, genuinely captured process tree, successful
   terminal, independent latest full pin and canonical drain. Join the next
   operation to its real predecessor without inventing a bridge request/result.
3. Verify the current saved recipe, model/runtime/profile and carried row-credit
   frames. For an ordinary owner that retained an existing capacity certificate,
   bind the certificate through its actual captured supervisor launch intent and
   continuation; a mutable path alone is insufficient. Reuse the existing
   geometry verifier and bound evidence; preserve the measured origin and limits.
4. Declare the exact old/new ordered mandatory stage inventory and the finite
   operation receipts already earned in this cycle. Resolve the cursor against
   those actual stage IDs, not an unchanged positional integer. Keep all full
   stage visit deficits, including long pending rows and incomplete DPO epochs.
5. Hold the existing controller/model leases and require all relevant owners to
   be drained. Verify original control bytes again, publish the verified latest
   checkpoint with the existing publisher, and commit only the declared cursor
   acknowledgement and runtime authority. Write durable intent/result evidence
   and support exact successor retry after a crash. Unknown successors reject.
6. Resume the canonical scheduler. A currently active direct owner continues
   useful SGD while this component is prepared; adoption occurs at its genuine
   next suitable boundary, never by manufacturing a historical drain.

The numbered policy is this natlang instruction. Crisp code is required only for
exact artifact/process identities, existing authority joins, durable snapshots,
lease/CAS checks, stage-index verification and the bounded publication commit.
Model arithmetic, parsing, optimizer factories, gradient execution and the
existing stage scheduler remain the shared implementations for both students.

Validation must cover both tiny model architectures, changed/missing authority,
wrong stage order, broken operation ancestry, incomplete stages retaining debt,
real earned policy/preference/ordinary frames, and exact crash/retry behavior.

The first implementation component factors the existing capacity continuation
verifier into `train/native_capacity_continuation.py`; its historical CLI
reexports the same verifier and policy names. This is shared exact mechanism,
not a new admission policy or a cloud/runtime adoption. All original verifier
function bodies and contracts remain identical. Validation: 107 capacity and
whole-HEAD/index continuation tests pass, including a real CLI-produced
certificate checked by the shared verifier; quick ratchets and TS pass.

The retained ordinary authority component accepts exactly one of the existing
actual MAX proof or an ordinary capacity certificate. The ordinary branch checks
that a genuine captured supervisor's original launch, spawn and intent bind the
actual trainer argv, recipe, restore parent and certificate SHA. Its configured
import environment must select the declared package. It snapshots those small
controls, compares saved model/profile, packing, offload and FP8 options, and
walks the complete existing capacity evidence chain including numerical cases
and parent/runtime identity. A path-only certificate, changed proof, mixed
authority or objective-bearing ordinary owner rejects. It creates neither a
resident plan nor a new measured-capacity claim. Genuine old bootstrap and
checkpoint/cursor bytes stay unchanged; current execution is not interrupted.

The executable route is `native_runtime_handoff --owned-operations ...` with
the actual bare recipe/package and exactly one actual qualification/capacity
authority. Its manifest schema is `natlang.native-owned-training-operations/1`
and lists exact handoff/readiness-receipt bindings in execution order. Static
manifest bindings reject before the checkpoint decode. The same verified decoded
full pin is reused within this invocation for reconciliation and handoff; it is
not persisted as a trusted loader cache. The owned receipt is explicitly bound
into the runtime proof and its exact state/cursor snapshots.

Publication uses the same checkpoint-state rule as the normal bridge. Durable
original/candidate controls and intent precede either mutable replacement. All
current control files must match original or exact successor bytes; a completed
retry never rewinds later earned state. The cursor acknowledges the actual stage
ID suffix (preference, then foundation), clears only an already-earned policy
pending round/current readiness, preserves every unknown guard and carried
deficit, and blocks dispatch until the matching runtime recipe is installed.

Owner-selected adaptive stage cadences are an optional
`supervised_stage_quantum_updates` declaration mapping on the existing scheduler.
The existing scalar remains the fallback. Thus preference can receive 250/eval50
while ordinary receives 1000/eval250; no stage is skipped or called complete.
Malformed/nonpositive cadences and undeclared stage IDs reject. This is declared
policy data with exact cadence verification, not a second scheduler.

The completed norm-entry owner used a previously reviewed read-only restore
observer instead of a literal trainer module command. This is an exact verifier
case: accept only that observer's pinned source bytes, its complete fixed flag
layout, a byte-bound original trainer argv, and the actual preceding parent.
Then apply the same output/stage/recipe joins to the original argv. Record both
observer and original-argv bindings in the chain. Arbitrary wrappers, altered
observer code, changed parents, or unbound argument files reject; the direct
trainer branch is unchanged. This recognizes genuine historical execution and
does not create a new launch, decode a historical optimizer, or relax readiness.

A verified owned-operation acknowledgement at the end of the complete finite
stage inventory is between cycles even though the durable cursor still says
`phase=sft`. When its exact candidate cursor has no pending policy round, all
stage IDs acknowledged, and controller state is `collect`, configure the next
actor and collector immediately. Otherwise the old pending-operation protection
would freeze the old actor through the configuration fast path. Unfinished SFT,
pending policy round zero or greater, and active learner state retain protection.
