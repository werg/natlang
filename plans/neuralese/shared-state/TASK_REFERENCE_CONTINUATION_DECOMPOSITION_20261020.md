# Observed task floors in normal recipe continuation

Policy: the supervisor chooses an honest useful task-performance floor for each
student, preserving task execution checks. LF uses the expressly selected
historical zero floor; Mellum uses its actual compatible prior-lineage observation.
Neither is a new base measurement or qualification of current weights.

The crisp preparer authenticates the selected reference evidence and changes only
`reference_successes` and `reference_provenance` inside existing task policies.
All packet/runtime/budget/cadence/source/model/optimizer settings remain exact.
It emits a normal candidate recipe and a small explicit parameter delta for the
existing normal recipe/preflight builder. Existing lineage continuation validates
adoption; no state, credits, qualified receipt or owner is produced. Current
weights must still satisfy the genuine existing task/runtime/gradient checks.
The reference is operational policy, adjustable after actual outcomes; it is
not a scientific matched-base requirement. No executing prompt changes.

Portable deployment uses one small immutable evidence snapshot for both policies.
Its producer independently authenticates each complete historical source first;
its per-role summary must exactly equal the derived provenance. Original logical
paths, hashes and byte counts are retained as scalar historical metadata, not
recursive deployment dependencies. Each recipe refers to the exact same staged

and runtime trees through the old result's nested evaluation inventory. The helper
checks local and declared remote evidence SHA/size and rejects altered summaries.
Only the three portable files (evidence plus two task policies) enter the cloud
recipe closure; the source-host preparation receipt remains its audit record.
