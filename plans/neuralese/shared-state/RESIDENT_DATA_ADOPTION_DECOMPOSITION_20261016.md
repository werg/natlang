# Resident native data adoption

The supervising natlang program decides which admitted data to add and when. Its instruction is: preserve the current foundation and held tasks, append useful admitted training sources, prepare their exact indexes while training continues, and request adoption at the next completed update. The mechanisms below verify that decision and commit it; they do not choose data or change learning policy.

1. **Prepare an append** is an outside-world service. Resolve the proposed recipe using the existing recipe resolver and data-continuation verifier. Require identical effective parameters, runtime inventory, foundation and every other stage; held inputs may append an exact class-preserving prefix. Validate the new source with NativeGraphSource outside the learner; bind its warmed indexes and complete row-prefix/scheduling metadata. Publish a content-addressed immutable request, then an atomic inbox pointer.
2. **Validate at an update boundary** is an exact verifier. Match the actual current generation, recipe, runtime and source. Recheck the proposal, immutable files, cached indexes and unchanged row prefix. A rejected request gets a durable error receipt; useful SGD continues.
3. **Commit adoption** is exact durability. One atomic current-generation document contains the complete recipe plan, recipe identity, source binding and configuration history. This is the commit point; legacy plan/current-binding files are repairable projections. No model, optimizer, RNG or row credits are changed. Readiness is invalidated by generation until new exact-weight receipts are produced.
4. **Continue exposure** is the existing shared exposure-deficit sampler and source-stream implementation. Close old iterators, retain all consumed visits, add zero-credit new IDs and rebuild pending batches. Keep the original communication foundation unchanged. Preserve held per-class visits/cursors using the existing append-aware selector. Check all old/new training groups against all old/new held groups.
5. **Recover** is exact durability. Before a restarted runner checks its plan, repair projections from the atomic generation. Before a trainer loads sources, select that committed generation; restore the actual checkpoint optimizer/RNG/credits and revalidate its exact old source prefix. An adoption is not a checkpoint and never claims unsaved updates survived a crash.
6. **Observe held classes** is a crisp accumulator over the existing graph-loss results. Report ordinary/communication weighted CE and accuracy without another forward or a change to selection, weights or forced boundaries.

The parent independently reviews integrated code and focused crash/resume tests before deployment. Runtime, arithmetic, held replacement, parameter changes and withdrawals require the existing stop/resume path. No production-format switch is implied by publication.

Preparation also computes exact new train/held GraphPlan physical-token and total KV-slot geometry outside the learner. An explicit runtime/model/packing memory-policy certificate binds supported limits and its evidence; batch packing targets are never interpreted as data limits. Unsupported requests remain pending, with an executable next step to adopt qualified shared offload/chunking support. A larger source is never truncated or discarded.

Before a numerical/runtime/parameter handoff, drain the actual owned trainer and retain a normal checkpoint containing the adopted generation. `native_resident --retire-checkpoint ... --trainer-exit ...` verifies the full optimizer/RNG/source generation and dead PID/start-time/boot owner before retiring only the metadata recovery journal. Runtime changes use the ordinary exact-state handoff. Prepared requests are metadata; they are not training exposure or current-weight qualification.

The current generation carries the complete source/recipe plan and invalidates old readiness immediately. The existing deployment builder accepts an exact `resident_adoption` file binding in release records, preserving the original launch recipe ownership while requiring the current recipe in readiness. The external provider bridge mirrors that complete small metadata closure and regenerates the existing waiting controller/bootstrap; it never ferries model state merely for an append. A stale controller cannot certify another generation.

Qualification: ledger `native-resident-final-owner-1996` passed 119 focused tests across resident adoption, native SFT, held coverage, readiness, deployment and recipe launch/inheritance; `native-resident-final-quick-1997` passed the required quick checks. Real tiny CPU model tests compare resident adoption with an all-data run, including train+held append and a crash after commit but before another update: backbone/interface tensors, full named optimizer state and RNG are bitwise equal, with every row credited exactly once. Injected pre-commit failure keeps useful old SGD eligible and retries after restart. These are mechanism tests, not target GPU memory/quality qualification. Production adoption remains disabled pending independent review and explicit target memory-policy evidence.

## Role-specific continuation rates

The supervisor's decision from actual held4500 evidence is to raise Mellum's four Neuralese role-token input/output rows to .003 while its reasoning rows, backbone and embedding transform retain 3e-6. `interface_row_learning_rate` is a narrow override in the existing named optimizer rate helper, applied after the optional all-learned-row rate. Omission preserves actual saved per-name rates. SFT, semantic phases and RL resume the same named moments; no alternate optimizer or reset exists. This parameter change uses a normal safe runtime/recipe continuation, never the data-only resident inbox. Diagnostics retain per-row changed coordinates and held marker probabilities; a nonzero gradient alone does not demonstrate useful learning.

## Reuse completed source geometry

The supervisor may reuse an existing complete CPU geometry pass instead of parsing the same admitted rows again. This is an exact verifier and outside-world preparation service, not a new admission or memory policy. Match the immutable prewarm receipt, all source/index/metadata bindings, tokenizer, roles, split and seven-file parser policy. Every newly appended row must be identical to a row in the receipt's covered suffix; conservative maxima from that superset are retained. Existing current-model capacity limits remain mandatory. A bound external CPU preparer may operate against the exact running package inventory, so preparation improvements do not require reloading a resident model. The learner's request and atomic adoption protocol remain unchanged.


Retirement also removes the adopted request pointer, under the same writer

retiring current authority. This closes the stale retired-pointer handoff

Within one CPU preparation, construct the proposed train and held trees first.
Reuse their already validated exact descendant source objects for old inputs and

match. Recheck every reused file's content and stat binding, including manifest
dependencies. For a source absent from those trees, use the existing complete
NativeGraphSource loader. No global monkeypatch, alternate row parser, changed
index policy or row/priority mutation is involved. Canonical append manifests
can name the old root as their first child to expose this sharing. All existing
prefix, scheduling, held separation, source-obligation and geometry checks still
run against the resulting objects. This avoids duplicate million-row metadata
constructions while preserving the admission decision.
