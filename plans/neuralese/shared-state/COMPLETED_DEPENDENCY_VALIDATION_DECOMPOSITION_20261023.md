# Completed continuation dependency validation

The supervisor's policy remains to retain every recovery, source, held-data and
controller dependency while returning GPUs to useful work promptly. The exact
validation and binding enumeration are crisp durability mechanisms.

1. Verify the bound completed continuation once in a single call.
2. Enumerate its exact recipe, package, controller and recovery bindings with the
   existing checks. Return both the freshly verified proof and the bindings.
3. Bootstrap and provider metadata consume that pair instead of verifying the
   same continuation immediately before an enumerator that verifies it again.
4. Keep the existing dependencies-only interface for callers that need it. Older
   immutable runtimes remain supported by the provider's existing two-call path.

There is no persistent proof cache, caller-supplied trusted proof, relaxed source
check, changed numerical code, or change to earned exposure. Each operation still
performs the full verifier and every dependency-binding check.
