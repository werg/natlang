# Complete preference capacity partitions

The supervisor chooses the useful capacity envelope and schedules both fit and
remaining cohorts. Crisp code verifies that decision against immutable source
admission and the production graph compiler. A token sum cannot stand in for
allocated KV slots: each invocation has alignment padding.

1. Authenticate the complete successful source admission and every original
   graph, source-row proof and objective. Keep its current protection binding.
2. Compile each complete chosen/rejected pair with the shared graph parser.
   Classify using actual physical token and positional KV counts.
3. Preserve original JSONL row bytes and held splits in both partitions; retain
   every objective row, source identity, and required visit explicitly. Emit
   usable source manifests and objectives, including held objective rows needed
   by the existing evaluator. Never admit rejected alternatives as positive SFT.
4. Publish a durable complete receipt only after all graph/objective/proof joins
   and output/source hashes pass. An existing complete output is verified and
   reused; an incomplete owned output is inventoried before regeneration.
5. Capacity classification grants no numerical execution certificate or earned
   exposure. The existing trainer/capacity continuation consumes these artifacts;
   the remaining cohort is an explicit scheduling obligation, never discarded.

Extend the existing acquired capacity partition CLI and mechanisms rather than
introducing another model-specific partitioner. Tests compare the exact compiler
geometry at a boundary where a naive token sum incorrectly admits a whole pair,
and check source/held/objective conservation, resume and tamper rejection.
