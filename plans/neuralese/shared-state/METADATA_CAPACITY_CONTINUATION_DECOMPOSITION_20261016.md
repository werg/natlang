# Continue measured capacity across scheduling and obligation changes

The supervisor may reuse actual memory evidence when a reviewed continuation
changes only CPU scheduling, pending-source accounting and orchestration. The
forward, backward, model layout, optimizer, precision, checkpointing, offload,
packing and seven source-validation policy modules must remain unchanged.
This avoids stopping useful training for a repeated identical GPU probe.

1. Independently review and bind both complete runtime inventories, the exact
   permitted file changes, the original measured certificate and saved parent.
2. Declare unchanged optimizer state and a conservative extra working-memory
   allowance, at least 64 MiB, plus the existing minimum 1 GiB free reserve.
3. Verify every inherited review/certificate/evidence link to the actual
   numerical and whole-graph memory cases. Accumulate previous allowances;
   never replace an optimizer allowance with a smaller metadata allowance.
4. Reject changed numerical code, execution identity, source maxima, parent
   provenance or insufficient host/device headroom. Publish honest inherited
   evidence with the original measured parent and separate source/current
   parents. A newer parent is explicitly not measured by this mechanism.

The existing `continue_native_capacity.py` is the crisp binding and arithmetic
mechanism. Natural-language independent review determines whether each listed
change really is metadata only; the filename whitelist alone is insufficient.
No new optimizer, memory measurement or source-admission verifier is introduced.
