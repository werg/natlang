# Resume interrupted actor-view publication

Policy: keep useful training and its exact full-state backup running. When an optional actor-view writer has already completed its temporary output, authenticate and publish that output rather than repeat a large write. A temporary file is never evidence of a verified inference actor.

1. Authenticate the unchanged complete training source and its actual integer step through the existing caller validation and source stat binding.
2. Select the same exact actor-only schema, weights, interface, model configuration and original-source identity as the canonical writer.
3. The operator may name one regular, nonsymlink temporary file within this exact full-source output directory. Safe reread and bitwise comparison of every selected value are mandatory. Reject missing, truncated, changed or different-source candidates. Preserve a rejected candidate as concrete failure evidence.
4. Authenticate stable candidate bytes, publish the immutable content-addressed target, fsync and write the existing exact receipt with the actual executing producer file identity. Delete the temporary name only after successful publication. The ordinary fresh writer retains its existing cleanup.

All mechanisms extend the shared native bundle writer used by both architectures. Recovery affects only CPU publication; it adds no optimizer updates and never grants training resume from a pruned actor. Source-host operation ownership and memory guards remain the caller's responsibility.
