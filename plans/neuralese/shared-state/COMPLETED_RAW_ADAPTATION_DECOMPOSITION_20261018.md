# Completed raw-operation adaptation

The supervisor may improve future training after any genuine completed raw operation. Raw work does not earn mandatory supervised-stage credits. The completed operation's exact optimizer, RNG, ordinary exposure, foundation exposure and pending recipe stages remain authoritative. Existing sealed rollouts retain their actor/runtime identities.

1. Authenticate the stopped controller and its exact plan, config, cycle cursor, sealed raw request, pre-operation production-state snapshot, completed result and artifact inventory.
2. Verify the actual full raw checkpoint once through the existing bridge verifier. Reuse that loaded object for subsequent adaptation; never manufacture a resident optimizer owner or a supervised training receipt.
3. Consume the completed raw operation through the existing `student_cycle` publication boundary. Its persisted production round must already account for the exact completed operation. Stop when the cursor reaches `sft`, before the first pending supervised stage. Record actual before/after controls and an idempotent durable intent.
4. Verify saved mandatory-stage frames directly against the existing recipe, without adding a visit, marking a pending stage complete, or consuming a DPO/SFT quantum. Explicit future data and parameter changes use the existing lineage handoff policy.
5. Reuse the completed-adaptation verifier/configuration/resident-installation path. Runtime or mathematical source changes still require their own qualified capacity/code continuation; raw consumption grants neither numerical readiness nor source-code authority.

Policy is this natural-language boundary contract and the existing adaptive production recipe. Crisp code handles exact file/process identities, schema and hash checks, the controller lease, existing transition invocation, atomic durable publication and verification. The mechanism is shared by LFM and Mellum. No model construction, rollout recollection, optimizer update, historical checkpoint decode, or inferred resident ownership belongs in consumption.

Validation must exercise a real serialized raw continuation, actual raw cursor consumption, retry after a partial control commit, zero new supervised credit, retained pending DPO/SFT stages and source obligations, and rejection of mutated request/result/parent/source/cursor authority. Existing supervised consumption/configuration remains unchanged.
