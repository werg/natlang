# Carry a measured derivative qualification across reviewed metadata changes

The policy permits reusing a successful complete derivative measurement only for
its exact unchanged saved weights, execution, trainables and derivative program.
The executing runtime retains its own identity; a carried measurement retains
the runtime that actually produced it. Fresh actor parity and whole-source
capacity remain mandatory.

1. Authenticate both installed package inventories and a reviewed exact
   metadata-only transition. Reject every unlisted file or changed hash.
2. Authenticate the previous actual successful phase, precision/FFN reports,
   exact optimizer inventory, actor identity and known pre-update failure.
3. Compare the actual new trainable inventory, actor identity and normalized
   trainer invocation with the old ones. Only owned output/control paths may
   relocate; classification parts must remain identical except producer paths.
4. Validate the complete original derivative proof, including all comparisons,
   tolerances and preserved gradients, against its original identity.
5. Return the original reports plus a separate equivalence receipt. Record that
   no new numerical measurement or optimizer update occurred.

These are exact provenance/equality verifiers, hence crisp Python. This is one
shared mechanism for both architectures. A new code transition requires its
own reviewed hash pair; an arbitrary caller cannot authorize numerical changes.
