# Attention index capacity continuation

The supervisor decides whether to adopt graph-local attention index reuse. This
continuation only verifies the already independently reviewed compositions; it
does not choose new arithmetic, enlarge geometry, or certify a new measured
parent. The existing capacity continuation verifier remains the one mechanism.

1. Authenticate the independently approved frozen code review and exact old/new
   shared-state hashes. Require every other package file to remain unchanged.
2. Authenticate four strict CUDA output/all-adjoint regression cases covering
   both ports under both frozen packages, including recomputation and graph
   lifetime. Authenticate a real production-size paired forward/backward result
   with unchanged state, exact gradients, and synchronized timings.
3. Preserve source geometry, parameter layout, optimizer state, all seven source
   policy files, and the existing transitive measured capacity evidence. Bind the
   latest drained checkpoint separately from the original measured parent.
4. Add an explicit conservative working-memory allowance and the existing
   reserve. Publish the same limits as inherited evidence; never call this a new
   maximum measurement or a speedup certificate.

These are crisp byte, schema, equality, and memory-bound checks. The adoption
decision and its practical timing remain the supervising natlang policy.

The paired qualifier uses the existing `native_memory.qualify_capacity` engine
for gradient release, optimizer gating, RNG restoration, and parameter-version
checks. It loads the exact bound old shared-state module as a reference, with
all remaining package files required identical. Separate diagnostic forwards
are explicit. It selects a complete admitted graph, compares streamed output
and full named-gradient digests, then records synchronized timings and a CUDA
trace without gradient hashing. No trainer or checkpoint is modified.

Standalone CLI bootstrap includes both the repository root and its Neuralese
package directory. Subprocesses cannot inherit pytest's in-process import path.
This is execution plumbing; importing ordinary saved-parent helpers remains
independent of the optional prefix-packing runtime.


Explicit prepared capacity requests (2026-10-17): before SGD, the shared SFT
caller requires a usable resident geometry certificate. An unsuccessful larger
frontier must retain a smaller passing certificate and allow useful training.
If every request failed and no capacity certificate exists, retain the failure
reports and stop before an optimizer update; the supervisor can resume the
previous qualified arithmetic path. Overall multi-frontier passed=false is not
itself a training barrier when a usable certificate was retained. This is exact
caller plumbing, not a new numerical threshold or a communication-readiness
waiver; both model families share the same guard.
