# Replay completed invocation metadata with its authenticated implementation

The current provider must preserve earned training when shared controller defaults
improve. A completed handoff records an exact future configuration, including its
actor command, and the numerical package that prepared it. Reinterpreting that
configuration with today's actor defaults can reject valid history and idle the
learner. The observed Mellum difference is solely the old actor entry's R22 path
versus the current factory's R24 path.

The natural-language verification rule is:

1. Authenticate the completed handoff, its consumed operation and checkpoint,
   original and proposed recipes, complete package inventories and exact inputs.
2. Reconstruct the declared future invocation using the active implementation.
3. If it differs, reconstruct it with the exact package recorded by the handoff,
   in an isolated CPU import context. Verify that package before and after replay.
4. Require exact equality with the bound future configuration. A newer default
   does not authorize changing historical commands, source membership, held data,
   checkpoint, runtime or scheduling declarations.
5. Continue the existing verification and dependency enumeration. This fallback
   grants no training exposure, capacity credit, readiness or model qualification.

Crisp helpers perform exact JSON/binding checks and isolated package imports. The
existing historical recipe replay mechanism should also execute invocation replay,
so package custody and CPU isolation have one implementation. No model prompt or
natlang authoring semantics change. Training weights, optimizer, RNG and exposure
are untouched. Validate subprocess isolation, package/input mutations and complete
handoff verification, then validate the actual Mellum artifact after full loading.
