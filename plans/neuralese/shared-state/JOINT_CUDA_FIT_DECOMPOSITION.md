# Full-size joint native CUDA fit diagnostic

Policy: determine whether the shared production semantic and native policy
objectives can update both actual architectures together on the available DGX,
while cloud production keeps training. An active historical task evaluation
retains its resources. Select a complete genuine admitted communication pair
that fits diagnostic memory; never truncate or fabricate the graph. This check
is architecture/kernel/gradient evidence, not foundation readiness or model lift.

1. Verify source, selected row, tokenizer, base inventory and model precision.
   Use the existing native factory and sparse reasoning-row upgrade. Crisp
   exact binding; no new prompts, training data, tokens or harness semantics.
2. Use the existing production triton-experts backend, deferred shared MuonSR
   optimizers and SemanticStateVAE dimensions. Run real VAE, joint control /
   cross-model consumer, then distillation backward and updates. This is an
   instrumented diagnostic of existing objectives, not another trainer.
3. Capture real native writer/read state and incremental action likelihoods on
   each resulting full-size model. Exercise the existing replay and packed
   native GRPO objective with explicitly controlled distinct outcomes. The
   fixture outcomes do not claim an oracle reward or an on-policy production
   collection. Record identities as in-memory diagnostic state, not a saved
   trained checkpoint or fabricated readiness receipt.
4. Check finite losses/gradients, actual parameter/optimizer changes, exact
   writer/read replay behavior, and measured memory/time. Record any blocker
   without replacing it with a tiny fixture or silent precision fallback.
5. Reset and record the selected backend's actual projection counters for each
   semantic phase and policy update. Reject a claimed FP8 phase with no executed
   FP8 projection, even when configuration names eligible modules. This guards
   the dispatch gap found after the first fit check; configuration alone never
   establishes kernel qualification.

All code here is crisp numerical verification and resource instrumentation.
Production task choice, adaptation and readiness remain existing typed policy /
controller interfaces. No new checkpoint schema, allocation, trainer or queue.
