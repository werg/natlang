# Classification recipe continuation

Policy: a running native stage may accept an explicit classification proof while every training, held, pending and predecessor input remains exact. No stage completion or new exposure is granted.

1. Crisp verifier authenticates the declared proof, exact current train and held hashes, zero model/update work and producer artifact closure.
2. Existing recipe handoff records this as a metadata classification continuation and retains the lineage identity and earlier inputs.
3. Existing trainer validates the full proof against actual loaded source/index entries before reattributing exact-bound existing row counts. Optimizer, RNG, source rows and quotas are unchanged.

Crisp code is necessary for exact hashes and continuation identity; no model-facing policy changes.
