# Mandatory sources pending an execution envelope

The supervisor's natural-language policy is to train every usable admitted row,
activate it as soon as the actual execution envelope supports it, and continue
useful cross-model work while capacity work remains. Source eligibility is not
execution qualification or earned exposure. Existing source quality and protected
split decisions remain authoritative.

1. The source-admission service binds the complete cohort, unchanged long-row
   partition, and audit/partition evidence. `declare_pending_native_sources`
   obtains exact semantic row identities through the existing NativeGraphSource
   parser, with the actual provisioned student tokenizer. It produces immutable
   declarations, not another progress database.
2. The shared SFT service verifies every declared file/hash and tokenizer. Before
   any update, it checks each active row against its pending semantic binding.
   Existing native-continuation frames own all required and earned visits.
   Declarations add quotas and zero credit; omission of a flag cannot erase old
   obligations. Activation retains the one existing row credit and discharges
   only the pending classification. No optimizer, weights or RNG are reset.
3. At a checkpoint the same progress frame carries pending bindings and source
   dependencies through semantic and RL objectives. Whole-SFT completion requires
   all quotas. A separately qualified communication foundation can progress while
   ordinary obligations remain. Pending-only deficits do not repeatedly schedule
   empty CE updates; new active source identities schedule actual continuations.
   A new pending-only declaration receives an explicit durable source-admission
   receipt bound to the parent and child checkpoint, with zero optimizer updates
   and incomplete whole-SFT status. Restart retains that receipt before the
   existing shared merge/refresh, rather than faking a learner quantum.
4. Recipe and provider services include complete immutable declaration/source
   closure in transfers. The unchanged shared trainer executes activated rows;
   neither this metadata nor the partition authorizes a capacity change.

Crisp code implements exact parsing, hashing, binding/credit verification,
checkpoint durability and existing service invocation. No new model-facing text,
new decision policy, separate optimizer or parallel exposure authority is added.
The source declaration is independently reviewed before recipe adoption.

The capacity derivative receives a new immutable corpus ID. It retains the
original source-eligibility evidence and unchanged full-cohort identity, declares
ONLY fit manifests as training entrypoints, and binds all remaining rows to the
same pending obligations. The full aggregate is provenance, never another source
to mix with its partition. Registration and execution qualification remain
separate; no live registry is written by the proposal helper.

Declaration CLI outputs use paths relative to each declaration's directory for
full-cohort, pending-role and evidence files. The same immutable bytes resolve
inside the transferred corpus on another machine. Returned runtime bindings are
resolved locally; no DGX absolute source path is required on a sandbox. A new
portable declaration/proposal version is published rather than modifying a
previous immutable declaration.
# Held capacity views

Capacity-derived admission declares a fit held entrypoint separately from a
protected long held entrypoint, with exact row counts and explicit nulls for
empty views. The trainer evaluates the fit held view under its measured
geometry; long held rows retain their test split and remain protected until
they can be evaluated. They never become training obligations or training
examples. Crisp proposal construction reuses the existing exact partition
manifests rather than parsing, changing or silently dropping held graphs.
Resolve logical cohort symlinks before comparing bound audit paths so a
registered logical path and its physical data path identify the same evidence.
