# Authenticate the installed recipe before replaying resident appends

Policy: never invent resident history, weaken current-policy SHA checks, or stop
an independent student's useful training because another student's initial
configuration failed before launching work.

1. Prefer the exact declared recipe in the resident prior/history as before.
2. If absent, require the existing fully verified drained-recipe transition.
   The resident's actual prior recipe must equal its old plan; the installed new
   plan must be an exact prefix of current code/device/handoff/adoption metadata.
   The first new adoption must name the new plan's exact digest as predecessor.
3. Replay the existing strict source-append contract from the verified installed
   successor through every actual new resident history entry. Return its real
   final current-policy SHA and original lineage. Never edit initial/current or
   fabricate a history entry to make the guard pass.
4. A failure during initial student configuration holds that student and records
   the exact declaration/config identity and error. Retry after those inputs
   change, while independent students continue. Errors after work starts, global
   plan failures and unknown worker ownership retain existing shared stop/drain.

The policy above uses one shared coordinator. Crisp code performs exact proof,
plan-prefix, source-contract and lineage checks, then records per-model blocked
configuration status. No model-facing feedback, numerical change, new worker,
checkpoint/state rewrite or earned exposure is introduced by verification.
