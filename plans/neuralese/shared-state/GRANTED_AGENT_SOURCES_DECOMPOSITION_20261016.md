# Granted SWE-chat, MiroVerse and MidTool sources

## Natural-language service contract

`NormalizeGrantedAgentSource` takes a pinned source file inventory and returns
complete original sessions, explicit nonpositive/preference alternatives, and a
catalogue of source material whose conversion or relational join remains owed.
The existing full-session exporter, connected-source protection, decision holds,
native renderer and admission audit remain the only downstream pipeline for both
students. Source curation is not a locally executed correctness oracle.

1. Authenticate every selected file against the pinned revision and exact
   immutable bytes. A completed file subset is an explicit snapshot, not a claim
   that acquisition of the source catalogue has completed.
2. Preserve the original complete ordered messages, reasoning, tool declarations,
   calls, observations and compaction contexts. Keep original identifiers,
   source row addresses, actor metadata, split and task/repository group closure.
3. Interpret explicit upstream outcomes conservatively. Failed or rejected
   actions never become positive targets. Retain their original bytes and
   preference/quality facts for the shared nonpositive/contrastive consumers.
4. SWE-chat raw transcripts are the complete representation; normalized tables
   are evidence/indexes and alternate views, never duplicate training sessions.
   Parent/child edges require unique spawning tool-use identity plus task_pk,
   compatible child context and observed parent reception. Missing/ambiguous
   joins remain explicit obligations. Never join children by session_id alone.
5. MiroVerse SFT preserves every source subset. DPO retains both alternatives and
   the preference binding; shared prompt identity keeps alternatives in one
   protected group. MidTool preserves the full tool-domain and text inventory.
6. Publish exact file/row coverage, rejects and pending relational/catalogue
   obligations before the existing source and native graph admission verifiers.

## Unit decomposition

- Selection, quality eligibility and recovery remain these natural-language
  instructions and the existing shared source/admission policies.
- Receipt verification, format decoding, event ordering, role/channel conversion
  and exact relational joins are crisp helpers: they implement externally
  specified formats and exact identity, not a second quality policy.
- Source-specific parsing lives in one shared acquired-source module, registered
  once in `agents.CORPORA`. There are no per-model source pipelines.
- Full-session export, weighted prompt/tool context, failed-action masking,
  tokenizer rendering, source-closed held protection, durable conversion and
  immutable admission reuse their existing shared implementations unchanged.

## Qualification and outstanding scope

Require actual pinned schema fixtures, full content/tool/reasoning retention,
negative ambiguity/outcome cases, byte-bound partial acquisition, and both
production HF tokenizer render/conversion checks. Catalogued but unavailable
files and unsupported source structures must be explicit rejects/debt, never
silently counted as converted or trained. No native communication edge or
source-completeness claim is made merely by registering an adapter.

## Implemented format and execution scope

The shared registry entries are `swe-chat-acquired`, `miroverse-acquired` and
`midtool-acquired`. SWE supports native Claude event ancestry/forks, compact-v1
embedded dispatch/results, and Codex response items (including original base
instructions, custom calls and results). The actual source labelled Gemini in
its session index uses the same native Claude event schema; actor identity is
retained from the actual transcript/model metadata rather than guessed from
that label. A real two-event Codex test fixture lacks a request and is explicitly
rejected. The inspected real Codex subagent includes an encrypted/redacted task:
retain its complete source context as nonpositive, never invent the task.

Every original SWE event receives an export accounting row. Only whole-context
representatives carry positive candidates; auxiliary/index/alternate rows are
explicitly accounted and retain their immutable original consumer. Sessions,
logs and subagent task indexes are authenticated and prepared once for file
shards, with exact transcript-path joins. Completed producer/consumer edge
construction remains pending exact unique-spawn and actual-return proofs;
ordinary source SFT never claims native state exchange. Compacted duplicates
are held for the original raw consumer even when that raw file remains in the
snapshot's pending acquisition inventory.

Miro DPO chosen histories are source-preferred SFT candidates; rejected histories
are retained with a preference-only nonpositive flag, not falsely labelled
locally failed. The original complete pair is addressable in provenance for
subsequent preference objectives. Current graph conversion is positive SFT,
not a claim that a DPO objective has already consumed those pairs.

MidTool web/PDF/code use exact original document completion, with no invented
question or answer; agent rows prefer original `extra.messages/tools` over the
serialized duplicate text. Actual `api-traj` examples are qualified. Other
native `src` payload structures require their actual schema examples before
claiming format completeness; unsupported rows retain explicit conversion debt.

`acquired_snapshot.snapshot` and `acquired_agents.load_acquisition` provide an
explicit immutable selected-file receipt for useful conversion during large
acquisitions. They verify the bound full catalogue, pinned repo/revision, exact
selected bytes and LFS/Git identity, and every outstanding catalogue path.
`ACQUIRED_RECEIPTS[ref]` selects that snapshot without modifying the active
acquisition journal. Export/admission must retain its snapshot and catalogue
bindings; neither a subset nor downloaded bytes confer training admission.

Qualification: 49 focused format/reader tests passed; actual full-content source
examples from all three datasets passed both production HF tokenizers (19
focused cases, 6.23s, no GPU). These are numeric rendering/format evidence, not a
full-source audit, held closure, capacity qualification or exposure claim.
