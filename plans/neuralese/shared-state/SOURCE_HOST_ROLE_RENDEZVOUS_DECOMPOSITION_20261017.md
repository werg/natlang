# Source-host native optimizer rendezvous

Policy: each declared source host keeps its own student useful, preserves its exact optimizer/RNG/source credits and validates genuine complete communication readiness locally. A ready student continues until at least two declared participants have reported genuine eligibility. Then each owner drains its current operations and releases its actual latest parent. Shared semantic work starts only after all final releases and the actual participant assets are available; remote paths are never presented as local checkpoint authority.

1. Declare a disjoint, complete assignment of model names to source-host roles, an immutable common model/cohort/numerical contract, and each controller's explicit owned models. Default single-host scheduling remains unchanged.
2. Reuse the complete local raw release and readiness validators, including full optimizer restore identity, current checkpoint/config/recipe, whole communication cohort, full-parameter gradient/runtime and task evidence. Publish immutable eligibility snapshots while useful local cycles continue. Eligibility is not optimizer release or permission to consume a remote checkpoint.
3. Exchange only bound role metadata. Once at least two declared models have genuine eligibility for the identical contract, stop new submissions, drain owned operations, revalidate the actual latest local parents and publish immutable final role-release proofs. A missing or invalid peer never grants readiness or stops useful independent work.
4. Aggregate exact final releases with one owner per model, unchanged cohorts and explicit source-host/controller/drain provenance. Source-host evidence remains source-host evidence; no remote local-path or live-owner fiction is introduced.
5. Before a semantic participant is consumed, require exact locally available checkpoint/recipe/readiness assets matching the released identities. Existing model loading and semantic-stage verification remain authoritative. Two genuinely ready, usable participants trigger the existing shared stage; a pending transfer is executable pending work, not completed readiness.
6. Preserve current raw cursors/bootstrap authority and ordinary deficits. Use existing durable JSON, binding, process ownership and readiness mechanisms; add crisp role-assignment, immutable proof, exchange and asset joins only. Tests cover single-host compatibility, useful work while peers are missing, release after real readiness, duplicates/tampering/wrong cohorts/live owners, resumability and actual semantic asset gating.

7. Declare exactly one semantic consumer role (Mellum for the current two-role deployment) so a single optimizer owns the joint stage. Other roles remain truthfully released. A future third participant is not a barrier for two genuinely qualified models. The designated consumer itself must release its local raw owner before loading any semantic models.
8. Run `scripts/coreweave/native_role_exchange.py --config ...` on the SDK owner host. Its bound plan/resource allowlist names existing roles; it relays immutable small proofs monotonically. Only the existing semantic controller emits a consumption request after final releases. The service then uses the existing native portable bundle, provider dependency enumerator, private ferry and target asset verifier. Mellum's local checkpoint stays local; the smaller remote LFM parent is transferred once for actual consumption. A durable exact asset manifest enables the existing native semantic stage, whose model, recipe, optimizer and held-data checks remain unchanged.

Crisp scope: role partition verification, SHA/byte joins, immutable publication, monotonic transport, process ownership and SDK/file I/O are exact mechanisms. The recipe retains the natural-language training policy and explicit numerical/communication requirements. No new model-facing prompts or mathematical implementations are introduced.

Transported metadata retains both semantic recipe identity and physical file hashes, the complete inherited-recipe file closure, original trainer launch/exit guards, explicit and implicit resident snapshots, foundation source closure and v2 task-score evidence. Target installation is immutable/no-clobber. A legacy saved parent without recipe provenance additionally requires a real local checkpoint alias at its original readiness path, pointing to verified independently copied bundle bytes; an occupied different artifact is a repair, never overwritten. The existing `load_participant`/`validate_ready` fallback executes unchanged against those actual files.

Validation: 124 focused protocol/readiness/provider/recipe checks passed, plus both actual CPU LFM and CUDA FP8 Mellum RL→SFT→RL update/restore tests (2 passed, 20.85 seconds). Quick checks passed all 22 ratchets and TypeScript. These are local integration checks, not production model qualification or deployment. The standing full-check owner will cover the published integration.
