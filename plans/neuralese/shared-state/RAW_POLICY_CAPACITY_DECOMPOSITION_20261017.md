# Qualify the actual restored policy objective before SGD

The recipe chooses whole-episode RL and retains ordinary successful tasks. A
policy learner must demonstrate that its actual admitted graph/objective fits
before its first optimizer step. SFT capacity is separate evidence.

1. Admit the original complete episodes with the existing replay verifier.
2. Bind the exact derived graph source, policy objective and artifact archive.
   Select complete examples maximizing physical tokens and KV slots; retain
   every example and loss unchanged.
3. After the existing model/optimizer/RNG restore, verify those source-bound
   cases and additionally select maximum physical/KV production batches from
   the actual pending schedule. Use the existing packed loss and read-only
   capacity checker, with the real policy objective and backend.
4. Require finite backward execution and actual configured FP8 projections.
   Restore optimizer/RNG/backend state; award no exposure or optimizer update.
5. Persist exact evidence. Resume reuses it only for the same source, objective,
   runtime/packing and authenticated saved continuation, retaining the actually
   measured parent identity. The checkpoint also carries the authenticated proof payload so a transported
   continuation does not depend on the original worker's proof-file path. Failed
   qualification blocks policy SGD. Collection
   and ordinary all-failure SFT seeding remain available.

These are crisp admission, execution verification and durability mechanisms.
There is no new loss, kernel, masking, truncation or model-facing instruction.
Held evaluation remains ordinary CE; training capacity uses the policy loss.

The frozen-runtime composition additionally takes only the published selected-case
byte-retention hunk from `211cc84ff`; sampled cases, ordering, objects and the
sealed collection SHA remain unchanged. It imports no later model/RMS/kernel or
source-policy changes. Both-port actual policy backwards preserve all optimizer,
parameter and CPU/CUDA RNG values before the same loaded model performs SGD;
Mellum additionally executes both supported expert FP8 input-gradient recipes.

The native policy CLI consumes the parent's communication-foundation, foundation
scheduling and resident-directory/capacity arguments instead of forwarding them
to the sampled-policy trainer. They still belong to seed and mandatory SFT. A
policy stage uses its own admitted episodes and fresh objective-capacity gate;
it cannot borrow authority to adopt the parent's supervised source manifest.
