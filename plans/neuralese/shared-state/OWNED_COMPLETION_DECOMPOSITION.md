# Successful in-process trainer completion

The supervisor chooses a safe recipe boundary and whether training should continue.
That remains the existing adaptive production policy. Exact completion evidence is
crisp durability plumbing, shared by both architectures.

1. While the actual captured wrapper is alive, bind its existing dispatch, launch,
   wrapper and continuation snapshots, and the absent future terminal path. The
   supervisor explicitly declares the reviewed wrapper's successful trainer-return
   contract. This is neither an operating-system exit code nor task qualification.
2. After that owner and its captured descendants drain, authenticate the wrapper's
   genuine successful-return marker against that predeclared contract and the
   original owner. Preserve the existing independent checkpoint pin and resident
   exposure checks. Legacy observed process exits retain their existing verifier.
3. Decode the complete checkpoint once, then allow the caller to carry the verified
   record/state pair through retirement and recipe/runtime continuation. Never
   discard earned optimizer/RNG/exposure state to avoid a second decode.
4. Historical checks use immutable control snapshots, so later cleanup or reuse of
   the original wrapper paths cannot rewrite the evidence.

No model-facing text, readiness, task success or training exposure is changed.
