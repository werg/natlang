# Recover qualified workspace settings after a failed owner

Policy: continue the exact earned full checkpoint after an interrupted run when
a useful workspace change passes its real numerical and whole-graph capacity
checks. A failed run remains failed; metadata recovery grants no optimizer,
exposure, task-quality, readiness or successful-drain credit. Preserve the
entire adopted data generation and any uncredited pending append.

1. Authenticate the actual failed bridge request/result, its captured live owner
   tree, and the resident initial/current records. Every captured owner must
   have exited; the resident owner must be that operation's captured trainer.
2. Decode the exact requested full checkpoint through the existing loader.
   Require optimizer/RNG and complete exposure metadata for the actual saved
   adopted generation and both source bindings. Never edit the checkpoint.
3. Authenticate the capacity certificate and numerical/whole-graph evidence
   actually inventoried by that failed operation. Require the same full parent,
   frozen runtime, model, objective and data geometry. Allow only an explicit
   FFN workspace chunk change; this mechanism cannot substitute source data,
   precision, batching, optimizer routing or model identity.
4. Under the resident lock, recheck owner death and compare-and-swap the same
   initial/current/pending records. Preserve all initial fields except the
   qualified workspace identity/certificate and an explicit recovery-intent
   history. Preserve the resident commit, plan, pending obligation, every row
   credit and the original failure evidence byte for byte.
5. Persist immutable before/intent/candidate/commit records. Retry only that
   exact transaction. The normal resident constructor and future append checks
   consume the corrected qualified workspace; all other checks remain active.

The supervising natural-language policy supplies the practical recovery reason.
The implementation is exact custody, artifact verification and atomic metadata
publication shared by both backbones. The normal trainer still verifies the
restored model and capacity evidence before any optimizer update.
