# Completed supervised adaptation

The supervisor chooses a useful boundary and the future recipe. This policy is
an owner-authorized adaptive production decision, not an invented completion.
The crisp mechanism authenticates the already sealed supervised request, its
completed provider result, actual saved optimizer and recipe/source contracts.

1. Verify the exact current cycle and completed stage at its current index.
2. Consume that result through the existing supervised publication mechanism;
   advance only that stage once, retaining the original result and receipt.
3. Reuse the existing recipe lineage handoff verifier for future source/LR
   changes. The actual saved frames establish which old stages have started.
4. Under the existing controller and operation leases, compare all old controls,
   publish a durable intent, then commit the future plan/config. Preserve the
   cursor and current full checkpoint; future inputs earn no credit here.
5. Refresh role-exchange plan bindings from the committed plan, separately from
   student readiness. Controller adoption checks this exact adaptation proof.

No resident owner or optimizer-drain receipt is manufactured. Full checkpoint
validation occurs once for preparing a boundary; normal historical proof reuse
retains immutable source/result/recipe bindings. Default runtime and numerical
qualification gates remain unchanged.
