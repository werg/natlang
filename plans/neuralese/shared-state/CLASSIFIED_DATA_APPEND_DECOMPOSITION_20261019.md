# Admit data and its classification evidence together

Policy remains comprehensive adaptive training: the owner admits useful new
sources; their exact execution/classification evidence accompanies the same
append. Admission creates no earned row visits or optimizer history. Crisp code
here verifies declarations, row identity and atomic publication, rather than
choosing which sources deserve admission.

1. Authenticate old and proposed classification proofs against their declared
   training/held source hashes and existing producer/parser authority. Require
   an unchanged held proof and verbatim prior training-part prefix. New parts
   accompany an explicit training-source predecessor.
2. Retain all existing resident append checks: stage/runtime/objective and fixed
   foundation, exact row order/bindings, held separation, quotas and capacity.
   Permit only the jointly validated classification input to change with data.
3. Verify each new part with the unchanged classification verifier against its
   actual loaded leaf. Derive a per-leaf scope that binds both full proofs and
   original source custody. Compare every leaf row with the newly appended
   actual suffix; reject repeats, foreign parts and omissions. Hash/size-equal
   physical copies retain both custody bindings explicitly. Historic index
   rows are not deserialized again; normal artifact hash checks still apply.
4. Perform that validation in ordinary and delta preparation and again before
   the learner's sole `current.json` commit. Reuse loaded immutable leaves;
   classification validation creates no graph execution or model allocation.
5. Select the proof from the committed resident plan at trainer startup and on
   live adoption, verifying its declared bytes. Persist the actual proof path
   and zero-credit history with the same checkpoint, optimizer, RNG and row
   exposure. Stale launch arguments cannot override the committed source/proof.

Actual resident preparation/adoption/recovery tests cover ordinary and delta
appends, rewrites, missing/foreign rows, and identical transferred sources. The
existing SGD crash/resume and recipe suites exercise the unchanged continuation
and atomic adoption mechanisms alongside these new proof checks.
