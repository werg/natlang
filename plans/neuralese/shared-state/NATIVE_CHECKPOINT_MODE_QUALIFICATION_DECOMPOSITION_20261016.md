# Actual-parent checkpoint mode qualification

The supervisor chooses a memory mode for useful production throughput and supplies the exact source-bound maximum cases. This policy remains outside the numerical mechanism; a failed candidate returns to the qualified checkpointed continuation with its exact parent and all credits.

1. Restore the actual production model, named optimizer moments and RNG.
2. On one existing admitted train graph, compare checkpointed execution with the declared candidate mode: checkpointed input offload, ordinary checkpointing, or no activation checkpointing.
3. Require bitwise loss and every named-gradient digest, without retaining full gradient copies or applying an optimizer update.
4. Run the already-required complete physical/KV maximum cases using the candidate options. Preserve the original weights, moments, RNG, backend and hook state on success or failure.
5. Publish a certificate bound to the exact options, runtime, source witnesses and parent. Combine independently passed cohorts; retain prior successful certificates when a novel larger cohort fails.
6. Resume useful production promptly. The supervisor records the selected recipe or an explicit checkpointed fallback; a failed candidate is never called qualified.

Exact source validation, numerical comparison, atomic artifacts and state restoration are crisp helpers in the existing `eval.native_memory` mechanism. No model-facing prompt or training objective changes. Both ports share the mechanism; production adoption is per-model and target-qualified.
