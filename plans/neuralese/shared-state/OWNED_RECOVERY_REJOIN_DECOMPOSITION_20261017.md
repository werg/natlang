# Earned owned work and source-host scheduler rejoin

The production recipe owns stage order and finite quanta. The natural-language
operation is: continue the existing model from its actual saved work, preserve
all remaining obligations, and resume the shared scheduler without replaying
an old actor or an already-earned update. This is bookkeeping for real work;
communication readiness remains a separate requirement for shared adaptation.

1. Authenticate the original owner, launch, captured descendants, terminal,
   immutable saved parent and exact operation inputs.
2. For an ordinary successful drain, retain the existing handoff verifier.
   For an explicitly recorded saved-update recovery, retain its failed terminal
   and failed original result. Verify the actual earned update boundary and
   descendant checkpoint ancestry; never manufacture a successful old handoff.
3. Authenticate the final owner using its actual authority: the existing bare
   direct-owner proof or the existing drained resident recipe transition.
   Do not replace genuine resident evidence with bare authority.
4. Read the final complete optimizer/RNG/exposure state once on its source host.
   Historical controls require their bound metadata, not another old payload
   transfer. A controller-only deployment does not stop a useful learner.
5. Under the existing controller leases, compare all prior control bytes,
   prepare exact successor state/cursor bytes, and publish with crash retry.
   Stage IDs acknowledge finite earned work; they never mark the full recipe
   or a partial communication cohort complete.

Crisp helpers are warranted for exact artifact/process identity, independent
pin custody, existing recipe-transition verification and durable compare-and-
replace. Selection policy stays in the declared recipe, ownership map and
stage scheduler. Both students use the same mechanism. No numerical model,
optimizer, packing, source parser or training state is changed by these joins.

Independent review and focused actual-owner tests precede deployment. Current
healthy learner processes continue while control assets and preflights are
prepared; any final drain is combined with a genuinely useful continuation.

The external resident portion extends the existing drained-recipe handoff rather
than installing a pretend recipe-runner runtime. Its explicit version-3 receipt
binds the captured launch import path and complete old package inventory. The
existing lineage policy computes the new plan; only that control plan is written.
The immutable external package is never copied or renamed. Original launch
controls are snapshotted so their later removal does not invalidate authority.

Owned-operation reconciliation accepts the existing genuine resident transition
as an alternative to bare-owner authority. A captured trainer's original recipe
is joined through every actual resident adoption to the final saved recipe;
source bindings, stage parameters, runtime and lineage remain verified. Tiny
actual-process/adoption fixtures exercise this path, with separate real LFM and
Mellum next-update optimizer/RNG parity. These tests grant no production capacity
or communication-readiness qualification.

The typed failed-monitor saved-update recovery is a separate follow-up, still
required before deploying the current LF historical chain. This change neither
relabels that failed operation nor claims that a controller cutover has occurred.

Bootstrap metadata cache evidence also binds every captured external launch control
snapshot. Both direct and later runtime-transition closures include these files;
changing a supervisor snapshot invalidates the cache instead of bypassing the
full authority verifier. This adds control dependencies only.

Typed saved-update recovery extends historical owned-operation accounting only.
The existing normal handoff and final current checkpoint verifier still require a
successful real terminal and full saved optimizer/RNG state. The explicit recovery
branch binds the original failed bridge request/result inventory, captured live
owner tree, actual failed terminal, independently pinned saved update and original
training readiness receipt. It never converts failure into exit zero. Exact small
control artifacts are checked against the failed result inventory; obsolete tensor
payloads are not decoded. Final ancestry and current full state remain checked by
the ordinary reconciliation path. This is crisp custody/accounting, not a new
training-selection policy or communication qualification rule.
