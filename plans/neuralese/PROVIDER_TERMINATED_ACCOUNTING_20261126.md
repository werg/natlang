# Bound provider termination accounting

Mechanism inventory before edit: `scripts/neuralese_data/vibestudio_campaign.py` owns native captured-provider evidence, receipt classification, retry selection, status, and the wave circuit breaker. `captured_provider_transport_errors` is the shared call-tree importer; `provider_transport_failure` and `infrastructure_failure` feed every scheduling consumer. Existing `NATLANG_CAMPAIGN_TRANSPORT_FAILURES_AS_GOAL_FAILURES=1` is the opt-out. `tests/test_vibestudio_provider_deadlines.py` covers exact provider request/call/model/error-event identity and cancellation negatives; campaign tests cover receipts and scheduling.

Engines and runtime generators are excluded: this change reads already-recorded `natlang.model-exchange/1` failures, without changing inference, sampling, captures, retries within a request or training targets. Node, Workerd and provider adapters emit the same canonical exchange envelope; Python/SGLang/wllama/llama serving is not called by this accounting helper. No historical receipt is rewritten.

Actual wave0093 scheduled-recovery root failed after a generation exchange with `Error: terminated`, nested `RemoteRpcError`, matching invocation/model and an actual failed model-request event. It must not spend a goal retry as though the model returned a wrong answer. This identifies the failed provider boundary only; physical connection/body reset causality remains open. A bare string, authored/tool failure, completed/recovered request, missing identity/event or cancelled call remains a goal failure/interruption under existing rules.

Checked boundaries: campaign receipt creation attaches the witness at `scripts/neuralese_data/vibestudio_campaign.py:234`; scheduling and wave accounting consume the same `infrastructure_failure` (`:374`, `:404`, `:701`). Generation is outside this mechanism: the Python engine contract accepts a `GenerationRequest` and returns generation data (`training/neuralese/natlang_neuralese/serve/engine.py:102`, `:377`); SGLang implements that API (`serve/sglang_actor.py:1019`). The ts-host callback reports model-turn deltas rather than campaign retries (`ts-host/src/native/agent.ts:682`). Offline training's canonical exchange reader independently excludes error exchanges (`ts-host/scripts/observed-workspace-evidence.mjs:463`); its masking/schema remain unchanged. Managed llama-server and in-page wllama requests therefore need no serving-policy change for a VibeStudio campaign receipt classifier. No engine is claimed qualified by these accounting controls.
