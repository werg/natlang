# Nested invocation lifetime and TypeScript entries

Independent review of e52 found two concrete omissions. A fresh task's inherited causal parent ID hit native-entry's ordinary-helper early return, suppressing the actual loaded pure TypeScript entry. A saved async frame could remain in a still-open task after its own invocation had completed, making late graph children arrive after parent custody was emitted.

Inventory: runtime.run/task.frame admission and deferred-entry resolution; kernel named/inline NL invocation and pre-model crisp/strict returns; native-entry compiled TS roots and same-task helper suppression; standalone NodeNativeRuntime recorded run and manually driven evaluation; StdSpan's separate synthetic trace lifetime; lexical adapter/soft-state getters; graph child registration/discard and sibling occurrence allocation. Other frame consumers spread the owning frame without creating a new invocation identity. Base ProgramLoader uses the shared runtime; Node/browser/Workerd SDKs all stage this same source. Managed llama/wllama/Python/SGLang model transports do not create these task frames. Physical browser execution remains a separate check; existing browser/Workerd/Node compilation and mocked-platform behavioral tests are not called paid model evidence.

Task-owned live-invocation membership now expires in finally, independently of task closure. Recorder-backed status is explicit: a fresh recorded child cannot infer custody from a synthetic span. New tasks revalidate the external causal ID at actual entry after awaits; an expired external edge is removed while their own authority stays unchanged. Ordinary same-task TS helpers remain native implementation, but a fresh loaded TS entry records its own typed crisp child and any actual NL descendants. Root suppression optout still preserves source ancestry.

A callback bound inside an ended invocation cannot retain that invocation's expired service/trace context. Bind at task scope before entering an invocation for callbacks intended to live for the task. No fallback widens old frame authority. Aborted parents supply no live causal edge to independently scoped work. Task.close clears its saved external parent frame, while graph custody retains only actual call IDs. Existing StdSpan receives lifecycle hooks without claiming durable CallStore capture; its older durable-record gap is a separate owned follow-up.

Tests use actual compileVirtualProject TypeScript entry/check/helper imports, actual evaluator service calls and promise continuations on Node/Workerd; no teacher/model requests. They cover crisp child/NL grandchild, helper suppression, nativeRoots optout, stale callback after completion with task still open, deferred child entry, aborted parent, standalone root, and task-bound versus expired invocation-bound callbacks. Original0064 captures remain immutable and are not retrospectively reparented.
