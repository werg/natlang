# Verified teacher trajectories to native graphs

The natlang policy is: use complete successful stronger-teacher executions as ordinary full-context action supervision, keep all useful distinct completions, preserve source and held boundaries, and never invent a communication edge from text markers. Newly admitted teacher sources may receive declared scheduling priority while the full recipe remains required.

1. Verify the immutable selected-case, teacher-runtime, transfer, response-file and current protection witnesses. This is an exact crisp verifier, not a model making an admission decision.
2. Verify each complete successful train trajectory belongs to its selected source and current allowed source groups. Retain full captured prompts, tools, reasoning and actual assistant action.
3. Use existing native_gold_packet and text_row_graph rendering. Reuse the existing four-role tokenizer provisioner and compressed-row writer. This is tokenizer/file-format plumbing, not another renderer or trainer.
4. Emit one ordinary action graph per complete captured action turn, context at lower weight, original response and trajectory provenance bound by SHA. No inferred state edges or consumer-gradient credit.
5. Publish exact conversion receipts; current corpus registry admission remains explicit, then use existing manifest append and row-credit scheduling for both students.

Source snapshot hashes, original execution identities and current held/source review are independent witnesses. A passed historical source selection is insufficient when current protections changed. Exact duplicates can be omitted with an explicit consumer-bound ledger; distinct successful completions of the same program remain useful.

A changing teacher queue uses `batch-source-bindings.json` with one exact packet,
selection proof and protection join per immutable collection receipt. The same
verifier checks legacy single-packet snapshots and multi-packet snapshots. Every
trajectory's full program must equal its own batch's selected program, not merely
share an ID or belong to another admitted packet. Receipts and graph provenance
carry the actual batch proof SHAs; current global protections remain additional.
