# LFM3 fresh-base HF/native inference comparison, 2026-11-01

This is a numerical investigation, not a task-quality or capability result. The fresh inference-only checkpoint has zero optimizer updates and zero earned exposure: `/home/werg/data/lfm3-rl-dgx-20261029/ops/fresh-instruction-baseline-1101/checkpoint.pt`, SHA-256 `110e645cc920b926f0726720613c95cd6964df1f0dc56f191dbef81e0f79beb7`. The comparison used the frozen `/home/werg/data/lfm3-rl-dgx-20261029/runtime-sft-multiupdate-v2-1101`, BF16 on GB10, with reduced-precision BF16 matmul reduction disabled. The vendored HF `modeling_lfm3.py` is byte-identical to the pinned instruction snapshot, SHA-256 `e8cd5254ea99ce6bd731b57b10908c2e8b5010ce8315341f895a38484885eeab`.

The one-model comparison ran the original HF implementation and `native_step` sequentially on the same weights. It restored the original HF norm forwards for the stock call and the native wrappers for the native call. A representative full tool-schema prompt contained 1,336 tokens; the comparison used the first 320 as prefill, followed by eight one-token cached decode steps, crossing the 256-token sliding window. Native-specific role/override output rows were excluded from logit comparisons. The prompt text and token-sequence digests are `529af4b73bd2cde90e946bb276f651586283ffbe012c7288eed0a48bb2f2351b` and `530b27f5069a6759561e38f57eaeee8a468f8f1113134d69ace2798e1ed2cfd0` respectively. The full result is `/home/werg/data/lfm3-rl-dgx-20261029/ops/fresh-instruction-baseline-1101/stock-hf-native-real-comparison.json`, SHA-256 `c8d9ba0013d2fa4d58b10f399e9fc371e86826de675c7412b23be1ea40564435`.

The result is **not exact stock/native equivalence**. Prefill logits had maximum absolute difference 5.5664, relative L2 0.05326, mean HF-to-native KL 0.02284 and top-token agreement 95.31%. One decode position had a different top token and relative L2 0.09150; another had relative L2 0.13067. These measurements characterize this exact model, prompt and runtime, not a general capability regression or a controlled task-outcome comparison.

Actual per-module captures locate the first nonzero prefill difference at the input of layer 2's post-operator norm, after two convolution layers and the first full-attention operation. Earlier norm boundaries matched exactly. The per-norm receipt `/home/werg/data/lfm3-rl-dgx-20261029/ops/fresh-instruction-baseline-1101/localize-norms.json` has SHA-256 `266114083e2d42b1e2fc1edd329dafeaa97322f6365dcf00fdaa2c88028e3768`. The earlier manual first-layer receipt `localize-layer0.json` (SHA-256 `6d3dbc4c8e1e12a5df78b93feadd1deadd07ef133902a01b4eaaf6111f054a19`) confirmed equal embeddings, operator norm, projection, gated input and convolution output, but its layer-level HF call retained some native norm wrappers; it alone does not establish full layer equivalence.

The immutable actual-path instrumented receipt `/home/werg/data/lfm3-rl-dgx-20261029/ops/fresh-instruction-baseline-1101/localize-first-attention-v4-actual.json`, SHA-256 `e43b81389a20f7ef76d8aaf7f3f62b6200be26066661b6f5fb2130f8fcf8ff70`, forwards the original HF and native functions while observing their real inputs and outputs. Q/K/V, rotated Q/K and actual attention operands are bit-identical; the first difference is stock HF SDPA versus native flex-attention output, max 0.001953125 and relative L2 0.0009971. Output projection relative L2 is 0.0015315. Earlier `localize-first-attention.json` double-applied a norm, and `localize-first-attention-v2.json` omitted native inference K/V casts; their large intermediate differences are **probe artifacts**, not evidence of model defects.

The exact-operand comparison `/home/werg/data/lfm3-rl-dgx-20261029/ops/fresh-instruction-baseline-1101/attention-sdpa-fp32-v6.json`, SHA-256 `cf7a22aa5bb4a63515eb9a4d6d0172dae1a5df987bd74cd4adaf35286b668785`, shows stock causal SDPA bit-identical to actual HF attention on those BF16 inputs. Against an independent no-TF32 FP32 SDPA calculation on the same operands, HF relative L2 was 0.00175945 and native flex 0.00175469. This supports BF16 backend-rounding divergence at this layer; it does not prove a semantic masking defect or establish full-model equivalence. The current shared arithmetic policy remains in place. A serving-only SDPA switch would leave packed training and imported graphs on a different path and is not an acceptable correction.

Independent CPU tiny-model regressions are committed in `dde5c88c4` and `fd5ee3836`. They compare stock HF cached prefill and token/chunk decode against native, including sliding/full attention KV suffixes and convolution state; verify actual native `SharedStateModel` cached decoding against a separately copied HF model; compare plain and tool-history serving request tokens to the pinned HF chat template; and compare ordinary packed, shared-prefix graphs to independent HF calls while checking cross-graph privacy. Those tests passed. They do not replace a real-weight GPU test of long imported graphs, BF16 prefix-sharing gradients or future arithmetic changes. The repository's existing real-weight parity tests contain historical measurements, but the current full CPU suite skips them; no current-runtime GPU receipt for those historical comments was located.
