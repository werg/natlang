# Revival of four dormant goals, 2026-10-12

Owner decision 2026-10-12, accepting plans/REVIEW_20261012.md (findings 3–4, recommendation 6): revive (1) the
harness as a Neuralese training bench, (2) the memetic optimiser over soft skills (M3), (3) RL (S7), and (4) serving
Mellum through our llama.cpp fork (S8). This page holds the current state and next steps for each. Results go into each goal's own plan
and are summarised in "Results" below.

Constraint while Mellum v4 trains (about 96–102 of 121 GB unified memory): DGX revival jobs claim 12–15 GB with
`--reserve-gb 2`, one GPU job at a time. Live experiments use LFM2.5-350M. No Qwen teacher runs on DGX (:8082/:8083
are down), so every live loop below needs a small local executor or author model, and that substitution is recorded
as a deviation.

## 1. Harness as a Neuralese training bench

**Exists.**
- pi port with the companion (`applications/pi/extensions/companion/`), the Neuralese provider
  (`--agent-transport natlang --agent-reader`) and views as stored calls (`host/views.ts`). The HARNESS_BENCH §5
  table lists these as done.
- An offline record pipeline: SWE-rebench/OpenHands → replay in pi → `teacher_training_turn.native/1`. Text twins
  exist for LFM and Mellum.
- `pi eval` runs one configuration over `applications/pi/tasks/*`. Six tasks exist.

**Missing.**
- The student has never run inside pi.
- There are only 6 tasks and no matrix driver.
- There is no per-run accounting of steps, context tokens or offer usefulness.
- No oracle companion, no live record format, and no qualified Neuralese writer. The direct artifacts are
  `direct-writer-pending`, so the Neuralese-views arm has to wait.

**First runnable milestone.** Run the HARNESS_BENCH §6.3 matrix on 20 tasks with an LFM2.5-350M student:
student alone vs student + text companion. Run it first on the base model and the local v8 export, then on Pop's
latest Muon-main export (requested from Pop on 2026-10-12). Record the results as a held cohort.

**Feeds e2e/Neuralese.**
- The same matrix gains the "student + Neuralese companion and views" arm once a direct writer qualifies. Its
  delta over the text arm is the end-to-end value of Neuralese delivery.
- The matrix's runs are on-policy trajectories. Verified successes become SFT/RFT rows, and pass/fail per group is
  the RL reward in goal 3.

## 2. Memetic optimiser over soft skills (M3)

**Exists.**
- `ts-host/scripts/skills/memetic-decision.mjs`: population search over seed texts, soft bodies and adapters on
  decision families.
- The 10-05 smoke on sms-spam: query .686 vs seed .520 and soft-gold .745, in 27.5 s.
- Imports still resolve against today's dist.

**Missing.**
- The heads it ran on (s3-pilot v4) are deleted, and the runtime is now Neuralese direct v1.
- The default init is now `in-context` through `/v1/neuralese/init_body`. It is untested on direct artifacts.
- The readout contract changed in 9d106d05.
- The author model (Qwen :8082) is down.
- The memetic optimiser scores on decision-case Brier, not on natlang task success.

**First runnable milestone.** Rerun the 10-05 sms-spam smoke with the same settings on a served LFM direct
artifact, with a local author model. Compare against the 10-05 numbers and treat any regression as a bug.

**Feeds e2e/Neuralese.**
- Soft skills are `Neuralese<Skill>` values read by consumers, which is the e2e capability in miniature.
- Next: change the fitness to task success on train-split natlang tasks. Make the population span crisp text +
  soft values + adapters. Use its winners as data for the e2e stage: values that consumers demonstrably read better
  than tokens.

## 3. RL (S7)

**Exists.**
- S7_RL.md (10-03 draft) and S7_ROLLOUT_CONTRACT.md (schemas).
- `rollout-episodes.mjs` (native-runtime rollouts, groups, scorer rewards; infrastructure failure → null).
- `rl/grpo.py` (HTTP GRPO on an adapter block through `/v1/neuralese/grad`/`optim`).
- The 10-09 smoke: a single GRPO step with ratio 1 and KL 0. Only boolq was scored, and six families failed with
  `driver` errors that were never diagnosed.
- The held-task eval (`evaluate_direct_task_packet.py`, `eval/task_packet.py` `classify_case`): binary task success,
  with infrastructure errors in their own class.

**Missing.**
- An RL handler in the shared recipe system.
- A link from the collector task path to replayable wire turns.
- Reward spread: LFM base gets 0/48 on the held tasks. The review says to treat that as a bug.
- Multi-round loop, token-level ratios, monitors, replay mix, and rollouts on direct artifacts or Mellum.

**First runnable milestone.**
- A current design: the reward is `classify_case` task success on the 72 train-split decision-rich rows (never the
  48 held rows).
- Rollouts on the served direct artifact. GRPO groups with a spread curriculum. RFT on successful rollouts when the
  spread is zero. KL to the pre-RL checkpoint through the drift monitor.
- The smallest smoke: K-sample groups on a few train rows → rewards → advantages, plus one update if there is spread.
  If not, diagnose the 0-success base.

**Feeds e2e/Neuralese.**
- RL trains the same weights the direct stages produce.
- Rollouts in which consumers read Neuralese values put reward on the writes, which is the e2e stage's objective
  with an exact reward instead of a distillation target.
- Pi matrix runs (goal 1) are a second rollout source.

## 4. Mellum via llama.cpp (S8)

**Exists.**
- Our fork `/home/werg/llama.cpp-neuralese` (branch `neuralese`) inherits upstream Mellum support: the converter
  `conversion/mellum.py`, `LLM_ARCH_MELLUM` and `src/models/mellum.cpp` (q/k norm, iSWA 3:1 with window 1024,
  YaRN on global layers), and the `mellum2` pre-tokenizer.
- Fork-side `llama-neuralese-server` and `-parity`, built 10-03/04.
- Weights: Mellum2.1-12B-A2.5B-Thinking only. This is our student backbone, so it is the parity base.

**Missing.**
- No GGUF has been produced.
- `llama-cli` and `eval-callback` are not built, and the builds predate HEAD.
- No parity against HF has been measured. The YaRN attention factor (1.277) on global layers is a specific risk.
- Not started: Neuralese extensions (markers extra_token_7/8, soft-input injection, the NeuraleseProjection head)
  and ternary/QAT weight formats.

**First runnable milestone.**
- Convert to BF16 and Q8_0 GGUF.
- Run on CPU, or on GPU within 12 GB.
- Check logit parity against a layer-streamed HF reference on a few prompts, including one longer than 1024 tokens.

**Feeds e2e/Neuralese.**
- llama.cpp is the declared deployment target, so it needs Neuralese ports.
- Next: projection head + soft-input embedding injection in `llama-neuralese-server`, with parity against our
  direct-artifact server. Then a ternary expert format matching QAT.
- This also gives a cheap Mellum rollout server for RL and the harness matrix.
