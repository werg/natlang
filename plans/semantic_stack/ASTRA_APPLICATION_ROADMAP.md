# Astra application-scale roadmap

The existing 120 valid programs remain useful source data. Simpler tasks are retained; only concrete correctness, visibility or runtime defects cause holds. The new slate adds genuinely different application-scale semantic work in separate projects, with no generic five-stage adapter and no count based on thin alternate questions over a padded folder.

## First implementations

1. **Saga Forensics** — [decomposition](../../applications/saga-forensics/DECOMPOSITION.md). Reconstruct effects from interacting journals, scoped identity rules, clock corrections and conflicting observations; derive a contingent minimal repair policy. About 30 NL files and 650–900 substantive NL lines, subject to removing any no-op stage. First deliverable is an actual end-to-end slice through correlation, adjudication and repair.
2. **Cave Mission** — [decomposition](../../applications/cave-mission/DECOMPOSITION.md). Reconcile survey frames into possible worlds, then synthesize an observation-contingent mission policy under gear and return constraints. About 29 NL files and 650–850 substantive NL lines, with separate map-hypothesis and belief-policy frontiers.

These numbers describe intended organization, not a success metric. Every file must produce a distinct typed semantic delta consumed downstream. Most implementation is numbered NL pseudocode with explicit branches, loops and state updates. Crisp code is limited to source I/O, exact arithmetic, services and verifiers. No fixture, file count or active stack depth substitutes for demonstrated semantic work.

## Later concepts, pending the first implementations

| Domain | Distinct task/data structure |
|---|---|
| Seed-bank genetics | Reconcile ambiguous pedigrees and design a trait-separating cross over inheritance hypotheses. |
| Treaty governance | Derive scoped obligations through delegated authority, accession, reservations and amendments. |
| Spacecraft operations | Plan contacts and commands under clock offsets, delayed acknowledgment and state-dependent permissions. |
| Materials assembly | Repair a process while preserving latent intermediate properties and resource compatibility. |
| Spatial audio | Diagnose a patch graph with return paths, mute scope and delay; choose a discriminating intervention. |
| Mathematical proof | Repair a proof DAG by resolving definition scope and minimizing a sufficient assumption change. |
| Data privacy | Derive a disclosure plan across relational joins, purpose limits and revocable consent in a fictional policy world. |
| Tabletop rules | Resolve simultaneous actions with replacement effects, interrupt windows and snapshot/current-state references. |

Do not mass-author these concepts as catalog rows. First obtain independent semantic review, source visibility, exact replay and live stage/literal-consumption evidence from the first two applications. Then expand useful architecture families while preserving different reasoning structures and whole-world split identities.

## Proposed source manifest boundary

A project manifest records `id`, `project_root`, `root`, `fixture_root`, typed `request`, `oracle_path`, `world_group`, service declarations/host module, comparison contract and readiness. The complete authored callable-folder graph is packaged without rewriting its NL instructions. Gold and exact grading artifacts live outside the model-visible project and fixture snapshot. Fixture facts are connected through actual downstream consumers; rejected observations and adversarial ambiguity have explicit roles rather than serving as padding.
