# Astra application-scale roadmap

The existing 120 valid programs remain useful source data. Simpler tasks are retained; only concrete correctness, visibility or runtime defects cause holds. The new slate adds genuinely different application-scale semantic work in separate projects, with no generic five-stage adapter and no count based on thin alternate questions over a padded folder.

## First implementations

1. **Saga Forensics** — [decomposition](../../applications/saga-forensics/DECOMPOSITION.md). Reconstruct effects from interacting journals, scoped identity rules, clock corrections and conflicting observations; derive a contingent minimal repair policy. Implemented23 NL files/535 total lines/355 body lines, with four consumed-literal plans. Independent source/oracle review and full typed reference replay pass; live qualification remains pending.
2. **Cave Mission** — [decomposition](../../applications/cave-mission/DECOMPOSITION.md). Reconcile survey frames into possible worlds, then synthesize an observation-contingent mission policy under gear and return constraints. Implemented25 NL files/558 total lines/374 body lines, with separate map-hypothesis, belief-graph and minimax-value frontiers. Full typed source replay,22 external verifier controls and independent source review pass. The conditional-anchor-v2 repair awaits a new live diagnostic; no complete live qualification.

3. **Treaty Obligation Ledger** — [decomposition](../../applications/treaty-obligation-ledger/DECOMPOSITION.md). Fictional institutional authority, scoped rule changes and time-sliced obligation truth maintenance; proof hypergraphs and discovered-evidence deltas. Implemented28 NL files/571 total lines/351 body lines, five scoped literal sites and a substantive minimal-support reducer. Independent24-entry source/oracle review,32 exact controls and full typed canonical replay pass; live qualification pending.

4. **Turn Window Adjudicator** — [decomposition](../../applications/turn-window-adjudicator/DECOMPOSITION.md). Fictional tabletop event rewriting with captured/live references, interrupt windows, simultaneous deltas and after-resolution triggers. Proposed26 NL callables; design only.

These numbers describe organization, not a success metric. Every file must produce a distinct typed semantic delta consumed downstream. Most implementation is numbered NL pseudocode with explicit branches, loops and state updates. Crisp code is limited to source I/O, exact arithmetic, services and verifiers. No fixture, file count or active stack depth substitutes for demonstrated semantic work.

Do not mass-author these concepts as catalog rows. Continue independent semantic review, source visibility, exact replay and live stage/literal-consumption qualification for each application. Expand useful architecture families while preserving different reasoning structures and whole-world split identities.

## Proposed source manifest boundary

A project manifest records `id`, repository-relative `source_root`, `entry`, `fixture_root`, `request_path`, `oracle_path`, `reference_path`, `source_world_split_key`, complete program/fixture file lists, typed call graph, external verifier, comparison contract and readiness. The complete authored callable-folder graph is packaged without rewriting its NL instructions. Gold and exact grading artifacts live outside the model-visible project and fixture snapshot. Fixture facts are connected through actual downstream consumers; rejected observations and adversarial ambiguity have explicit roles rather than serving as padding.
