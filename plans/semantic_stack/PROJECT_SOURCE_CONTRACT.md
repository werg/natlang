# Application-scale semantic source contract

This contract is for authored natlang projects whose algorithm lives in a tree of `.nl` callable folders. It does not replace the existing 220-program catalog adapter. A project writes its own `DECOMPOSITION.md` before implementation, mapping every decision to a natural-language function or instruction and justifying every crisp helper.

## Manifest and immutable snapshot

`project.json` names a stable project ID, source root, entry `.nl` file, typed request, task input snapshot, oracle file, source-world split key, comparison specification, provenance, license and any services. `program_files` lists every `.nl` and declaration file included in the source snapshot by relative path. `fixture_files` lists every model-visible task input by relative path. `oracle_path` is outside the model-visible snapshot. The packager hashes the exact manifest, source bytes, input bytes and oracle bytes; a later edit creates a new source revision.

The first packager is `node ts-host/scripts/inline-curriculum/package-semantic-application.mjs --manifest PROJECT_JSON --out FRESH_DIRECTORY`. Repository-relative roots and listed files are checked for traversal and symlinks. Design documents such as `DECOMPOSITION.md` belong in manifest metadata, outside `program_files`; the model receives the authored executable tree and declared inputs. `input_bindings` maps each declared root argument to `{ "from": "request_path" }` or `{ "from": "snapshot_path" }`, so a project may have separate request and source-snapshot arguments. The package report records hashes and keeps training admission false. An invariant-only oracle stays held until its external checker and independent semantic witness review are qualified; packaging does not pretend that a canonical witness is a complete byte-equality target.

The manifest also declares `typed_call_graph`, `scoped_literals` and `iteration_reducers`. These are audit claims about the project, not a template from which the packager rewrites its functions. The packager checks that declared `.nl` paths exist, every named child is callable from its actual parent folder, referenced types exist, service names are declared, and the model-visible root has the declared request/result signature. It preserves source text and folder structure byte for byte. A dependency outside the snapshot or an absolute/escaping path is an error.

Call-graph edges may use a direct callable child folder or an explicit `uses: [...]` entry in the caller's `.nl` frontmatter. External service implementations are packaged under `semantics.services` from declared host files, while only the declaration appears among model-visible program files. Loading the packaged root through `loadVirtualNatlang` is a source-topology preflight; it does not execute or grade the natural-language application.

## Execution and admission

The packager emits a Program/2 source with the complete project files and one pinned task input snapshot. Its first exact pass verifies path containment, type/signature availability, fixture/gold separation, provenance and split-world identity. A scripted reference, if supplied, is source/runtime replay evidence only; it cannot stand in for the app algorithm or establish answer quality. Teacher execution must actually call the authored root, traverse the relevant named branches, consume dynamic literal results, advance structural iterations and produce the typed result.

An optional `reference_path` points to one full typed result outside the visible roots. The packager writes that value only to a separately named `reference-replay-only.ir.jsonl` and records Program/2 source/type replay results in `package-report.json`. This replay removes technique requirements from its own reference case because a direct canonical return cannot prove the application used its real calls or iterations. The regular `source-package.ir.jsonl` keeps those requirements and remains held until an application-level comparator and independent semantic review are ready.

For an invariant-based application, `external_verifier_path` names a trusted repository `.mjs` module outside the visible roots. The packager binds its SHA-256 and the authored oracle into the regular Program/2 source. Its exported `verifyCandidate({value,oracle,inputs,fixture})` returns `{ok,issues,semantic_review_required}`; the shared collector checks the hash before calling it. It tests exact returned-value, source and fixture invariants, never supplies the semantic answer. The canonical source/type replay omits this hook deliberately. Both current application verifiers accept their authored reference and reject a wrong-identity mutation; they still return `semantic_review_required:true`, which leaves teacher rows quality-pending. A frozen teacher runtime locates the canonical checkout through `NATLANG_REPO_ROOT` or its working directory, since frozen code lives outside that checkout.

Answer comparison preserves explicitly ordered sequences, declared unordered multisets and exact IDs/numbers/booleans. Prose alternatives and alternate valid plans receive independent source-grounded review; a generic judge cannot override changed exact bindings. Stage and final-output review checks source-path/quote witnesses, distinct semantic contributions, actual child consumption, iteration progress, branch coverage and the project's exact verifier. Only a complete reviewed native trajectory enters the training corpus. Failed or interrupted diagnostics are not model-negative or DPO examples unless an assigned recovery consumer and correct preference pair are recorded.

Source size and semantic depth are mix labels, not admission limits. Valid easier projects and the earlier 220 cases remain eligible. The new slate should use application-scale organization because its tasks require it; no arbitrary file-count or call-depth threshold is encoded as a language rule.

The package report carries a non-gating quality audit: total `.nl` lines, numbered policy steps, declared graph nodes/edges and maximum call depth, scoped literal sites with their stated consumers, and an explicit pending review of whether crisp code displaced policy. Static syntax only describes the authored source; live traces must establish that literal outputs feed later decisions and that the branches perform the claimed semantic work. These fields help compare the new applications to larger existing projects and identify code-heavy regressions without excluding valid simple cases by size.
