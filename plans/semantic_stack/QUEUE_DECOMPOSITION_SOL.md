# Semantic-stack priority queue decomposition

This unit prepares generation work from the two authored catalogs. It reuses `scripts/prepare_luna_folder_campaign.py`, `scripts/start_reviewed_luna_campaign.py`, and `scripts/run_bonsai_queue.py` for queue construction, launch identity, worker ownership, and output accounting.

1. **Select useful generation work (natural-language policy).** `training/semantic_stack/selectPriorityWork.nl` says how to prefer reviewed sizable semantic programs, cover distinct operations and domains, and keep a topology diagnostic separate. `sol_priority_queue.json` records the author's concrete initial order. This is an authored snapshot decision, not a new dynamic scheduler.
2. **Check eligibility (exact verifier).** `scripts/materialize_semantic_stack_priority.py` verifies pinned source/review hashes, exact reference status, catalog readiness, a concrete sizeable fixture, matching visible file bytes, train split, source identity, oracle equality, and explicit absence of training admission. It does not infer semantics, override holds, create gold, or convert successful schema checks into admission.
3. **Materialize selected bytes (crisp plumbing).** The selector projects immutable Program/2 rows in the already authored priority order into a fresh JSONL and seals a selection manifest. Other catalog entries remain in their original catalogs with explicit pending reasons. Existing source replay and decontamination run on these selected bytes before the existing campaign preparer consumes them.
4. **Collect and qualify (existing pipeline plus semantic review).** Initial full cases first run a diagnostic to measure real call nesting and scoped captures. A pass needs actual active parent-child NL calls, per-item interpretation, structurally decreasing iteration, and correct semantic result. Teacher collection stores whole trajectories. About 48 live samples per source variant are still required before model-facing adoption. Full-corpus admission separately requires source split/provenance checks, semantic review, and registration.

The program catalog is broad by semantic operation. The initial generation cohort is narrower: eight expanded Astra cases and ten expanded Sol cases. The other ninety Sol programs are held source designs awaiting sizable fixture authoring and independent semantic oracles. No statement here credits a source-reference replay as an observed teacher trajectory.

## Replenishment

At the end of a reviewed batch, run the existing generation backlog report and inspect exact completion/accounting results. Expand the next held catalog designs in the committed order; each new fixture needs independent meaning evidence and a separately derived oracle, with whole-world split identities kept stable. Rebuild the common source adapter, rerun source replay and decontamination, materialize a fresh selection, then use the existing campaign preparer. Maintain the same supervisor and launch ownership on Pop. Do not append new cases to a frozen running queue.
