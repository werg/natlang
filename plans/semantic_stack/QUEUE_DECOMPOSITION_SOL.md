# Semantic-stack priority queue decomposition

This unit prepares generation work from the two authored catalogs. It reuses `scripts/prepare_luna_folder_campaign.py`, `scripts/start_reviewed_luna_campaign.py`, and `scripts/run_bonsai_queue.py` for queue construction, launch identity, worker ownership, and output accounting.

1. **Select useful generation work (natural-language policy).** `training/semantic_stack/selectPriorityWork.nl` says how to prefer reviewed sizable semantic programs, cover distinct operations and domains, and keep a topology diagnostic separate. `sol_priority_queue.json` records the author's concrete initial order. This is an authored snapshot decision, not a new dynamic scheduler.
2. **Check eligibility (exact verifier).** `scripts/materialize_semantic_stack_priority.py` verifies pinned source/review hashes, exact reference status, catalog readiness, a concrete sizeable fixture, matching visible file bytes, train split, source identity, oracle equality, and explicit absence of training admission. It does not infer semantics, override holds, create gold, or convert successful schema checks into admission.
3. **Materialize selected bytes (crisp plumbing).** The selector projects immutable Program/2 rows in the already authored priority order into a fresh JSONL and seals a selection manifest. Other catalog entries remain in their original catalogs with explicit pending reasons. Existing source replay and decontamination run on these selected bytes before the existing campaign preparer consumes them.
4. **Collect and qualify (existing pipeline plus semantic review).** Initial full cases first run a diagnostic to measure real call nesting and scoped captures. A pass needs actual active parent-child NL calls, per-item interpretation, structurally decreasing iteration, and correct semantic result. Teacher collection stores whole trajectories. About 48 live samples per source variant are still required before model-facing adoption. Full-corpus admission separately requires source split/provenance checks, semantic review, and registration.

The priority selector projects all 220 without omissions; the first 82 ordered cases visit each world once. This is source preparation, not live teacher quality or SFT admission.

`priority_full220.json` is the authored selection snapshot. The first six cases cover separate Sol worlds in maintenance, observing logs, film continuity, accounting narratives, philosophical argumentation, and project planning. `scripts/prepare_semantic_stack_pilot.py` is exact queue plumbing: it checks the selection/source/runtime hashes, copies the chosen rows to a fresh immutable pilot source, and emits one-case queues with correct physical indices. It neither chooses cases nor launches workers. Launch one or two one-case queues at low ledger priority after checking trainer headroom. Whole-trajectory semantic correctness, exact source witnesses, actual NL stage/literal use, and idiomaticity are reviewed per row; a valid source can yield a held trajectory without losing source eligibility.

The existing `prepare_luna_folder_campaign.py` cannot directly seal these cases: it expects a separate full reference-result JSONL and currently fixes each case at 60 turns/384 model requests, while substantial 24-record semantic programs have exceeded those collection ceilings. The semantic-stack pilot helper reuses `run_bonsai_queue.py` and its frozen runtime, and records explicit collection ceilings as resource limits. A future unified campaign preparer should accept the signed source review/reference proof and a measured case-size resource profile. This is an operational integration task, not a language limit or reason to hold valid cases.

## Replenishment

At the end of a reviewed batch, run the existing generation backlog report and inspect exact completion/accounting results. Review the next held expanded catalog cases in `next_expanded_source_ids`; each requires a second independent oracle check and source replay, with shared whole-world split identities kept stable. Future new worlds still need independent meaning evidence and separately derived oracles. Rebuild the common source adapter, rerun source replay and decontamination, materialize a fresh selection, then use the existing campaign preparer. Maintain the same supervisor and launch ownership on Pop. Do not append new cases to a frozen running queue.
