# Astra connected application world expansion

Status: source authoring plan, not a set of runnable or admitted examples. Existing valid simple sources remain eligible. These worlds reuse genuine application interfaces while changing the evidence structure and decision problem; no count is credited until original source, full typed witness, independent reconstruction and exact controls exist.

## Split and source policy

A world owns its complete directory tree, entity graph, source conventions, constraints and uncertainty. All paraphrases, counterfactual request variants, selected/unsubmitted choices and adversarial mutations derived from that world share one split key. Hold out entire worlds, including their private references. A new file layout or renamed cast does not create an independent world. The proposed keys below are distinct from existing worlds because their causal/epistemic/resource structures differ.

For each world: first author 20–40 connected source facts and a relevance map identifying which downstream judgment consumes each fact; then a full typed witness with exact service/verifier seams; then peer reconstruction and equivalence/negative controls. Source readiness, live qualification and training admission remain separate. Distribution breadth is measured in distinct source structures and decision branches, not file count.

## Scale without boilerplate

The first increment is five new independent worlds, one per application, selected from rows implementable with current types. Each must exercise at least one semantic branch absent from its application's first world and have a peer-reviewed relevance/decision map. The next increment adds the typed-state extensions above. Reuse existing NL stages where they already express the rule; add a connected callable only when it owns a new typed transformation consumed later. Never add one function per fact merely to increase code size.

A per-world manifest will record whole-world split key, source hashes, authored branch obligations, external reference/verifier hashes, independent review, source replay and separate live counters. Equivalent alternative policies and generated-ID renamings need positive controls alongside wrong-world/omitted-branch/false-premise negatives. A successful full typed reference is a source-validity witness, not a model trajectory.
