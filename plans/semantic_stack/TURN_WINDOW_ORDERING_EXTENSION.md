# Turn Window: source-governed ordering dispute

## Purpose and frozen baseline

The first Glass Garden source, fixture and canonical certificate remain frozen at c3fd2000 while Sol completes independent review. This extension adds a connected semantic branch to the same event interpreter. It does not invent a player choice or implement rule policy in TypeScript.

The present `resolveOrdering` asks whether applications commute but supplies no concrete alternative executions. The extension makes that judgment consume actual typed preview results, with an explicit selected-order witness and exact isolation from committed turn state.

## Second connected turn: Mirror Garden

Reuse the explicit fictional identities and starting board, with a separately versioned complete fixture and source-world split key. The altered source permits a submitted order choice for Cover and Mantle on PM instead of imposing Cover first. It specifies that the response sequence and PA-before-PM printed allocation remain fixed. The player submits Mantle before Cover for PM. No choice is inferred from which result is desirable.

The semantic fork has concrete consequences:

1. Both previews start from the same resumed board: A1 and M1 are Rowan's creatures; W1 is attached to M1; WARD is available.
2. PA is still reduced from three damage to two. Both previews retain that actual rewrite and its separate once-per-lineage capacity.
3. In the Cover-then-Mantle preview, PM becomes one growth and consumes WARD. Mirror's threshold of at least two converted damage fails.
4. In the Mantle-then-Cover preview, PM becomes two growth and consumes WARD. Cover is then inapplicable to that growth part; its negative decision cannot reduce growth.
5. The source-supplied PM order selects the second preview. The batch destroys A1 and gives M1 two growth. Mirror now queues two ink for W1's current controller Ilex, while Return still uses last-known Rowan and Scribe still uses captured Ilex.
6. Return, Scribe and Mirror resolve in their source-defined priorities. Final Ilex ink is three, Rowan ink zero; MIRROR is spent. Reprisal remains ineligible because its original token was already spent.

The Mirror source wording must refer to the actual converted quantity, not assume a preceding Cover application. This is an explicit authored rule change, not a hidden reinterpretation of Glass Garden. A paired missing-choice request uses the same semantic fork but must stop before committing either replacement result, returning the consequential order as unresolved.

Every candidate rule application reads one declared common before-board and its own current rewritten part. Preview reservations are branch-local. Merely exploring the first candidate cannot spend WARD in the second candidate or in the actual board.

## Typed graph extension

Existing `rewriteBundle` remains the only parent that can invoke its actual `applyReplacement` child. This respects callable-folder visibility and preserves one semantic implementation of replacement applicability.

1. `resolveOrdering` calls a new `enumerateLegalOrders` child. Its numbered NL steps classify source precedence, identify the finite disputed application identities and produce only source-legal candidate orders. A scoped literal returns one disputed relationship with witnesses; the parent inserts that actual result into the candidate constraints.
2. `rewriteBundle` receives an `OrderPlan` with candidates, fixed applications, source choices and unresolved legality. It initializes one independent `ReplacementState` per candidate from the same original bundle/beforeBoard.
3. For each candidate, `rewriteBundle` invokes the existing `applyReplacement.iterateOn` over that candidate's finite remainingApplications. Each actual child return updates only that preview's bundle, decisions and reservedTokenIds. No new semantic simulator is written in crisp code.
4. `rewriteBundle` calls new `compareOrderPreviews` with actual `OrderPreview[]`. This child calls `compareConsequenceProjection`, which judges whether differences in rewritten kind, amount, target or shared capacity can affect this source's later outcomes or triggers. A scoped NL result owns a typed `OrderDifference`, rather than a prose-only explanation.
5. `compareOrderPreviews` calls `bindSubmittedChoice` for a consequential difference. This child joins the actual submitted choice's subject, source-defined chooser and relative-order terms to candidate application identities. It returns the selected candidate or a witnessed missing/illegal choice. It cannot select by numeric benefit or storage order.
6. `rewriteBundle` consumes the selected actual preview as its `RewrittenBundle`; it does not silently recompute a more convenient sequence. An unresolved consequential choice returns no committed reservations or rewritten batch. Equivalent candidates may use a stable presentation choice only after an NL equivalence result is returned and retained.

Proposed new declarations: `OrderConstraint`, `OrderCandidate`, `OrderPlan`, `OrderPreview`, `OrderDifference`, `OrderChoiceBinding`, `OrderResolution`. The returned resolution preserves source choice identity, selected candidate identity, preview input revision and all actual comparison findings. Generated candidate IDs may vary consistently; original clause/intent/part/token identities remain exact.

The four new functions add task-specific interpretation and comparison, not forwarding layers. Expected total: approximately30 NL callables and an additional120–180 numbered-pseudocode lines, adjusted to the actual responsibilities rather than a line quota.

## Termination and exact seams

Candidate orders range over a finite source-derived application set. Enumeration follows structural recursion over remaining application identities and respects source constraints; it has no arbitrary candidate cap. Preview iteration consumes each candidate's remainingApplications. The outer turn's existing finite work-slot measure remains unchanged.

Crisp operations are limited to copying immutable preview inputs, checking source IDs and nonempty exact quotes, validating candidate permutations/precedence, comparing unchanged before-board snapshots, checking branch-local token reservations and applying the selected already interpreted delta. Whether rules commute, whether a difference matters and which submitted choice governs remain NL decisions.
