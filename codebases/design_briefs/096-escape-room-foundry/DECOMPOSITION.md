# Escape Room Foundry

The room is represented as a player-visible state graph. Puzzle prerequisites, clues, solved flags, props and exits are explicit state transitions; the graph has parallel branches that merge only where a clue is genuinely available. A deterministic verifier enumerates reachable states, checks required-goal reachability, cycles, soft locks, repeat actions, and emergency exit invariants. NatLang interprets whether each clue fairly communicates the intended reasoning and where plausible misreadings create ambiguity.

Playtest branches include out-of-order discovery, missing or broken props, sensory opt-outs, and wrong answers. Every exceptional state must retain staff recovery without relying on designer knowledge. Accessibility variants preserve equivalent puzzle information and route to the same progression state. Operations packaging binds setup and reset inventories to a session; a pre-session state scan catches missing props, and reset verification prevents one team's state from leaking to the next. Human safety and enjoyment reviews remain independent of mathematical solvability.


Reset verification is a separate resumable operation from room design. The package operation emits a setup/reset checklist, but it cannot mark a physical reset complete. `verifySessionReset` consumes a current readback bound to the exact room revision and next session, checks one observation per expected prop plus cleared puzzle flags and emergency-exit availability, and updates the retained checkpoint only from the supplied receipt. A missing, duplicated or mismatched observation leaves the reset unverified.
