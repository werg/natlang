# Documentation-behavior synchronizer

Every documentation promise is attached to its precise page span, audience, and applicable release. Probe plans pin identical release and environment details; an unrun probe remains a plan. A mismatch is adjudicated against requirements, release decisions, tests, and observations, so a product defect does not get disguised by changing the docs.

Repair bundles preserve unaffected claims and exact page bases while coordinating examples, tests, and release notes. Secret-bearing code samples block export without copying secret values. Deprecated service examples carry their environment and a reviewed replacement. Concurrent page edits trigger a rebase and claim revalidation; translated edition lag is tracked separately from translation quality. The bundle can be proposed only when all published examples and claims refer to one target release.
