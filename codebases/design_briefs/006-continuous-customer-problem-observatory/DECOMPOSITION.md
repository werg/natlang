# Continuous customer problem observatory

The observatory keeps an episode grounded in the customer's attempted job, desired outcome, obstacle and consequence, and separates a feature request from the experienced problem. Customer identity migration is versioned before counts. Incident linkage distinguishes copied messages and one outage's ticket volume from independent discovery, while retaining failures repeated on distinct occasions. Problem concepts track stable IDs and counterexamples across topic renames.

`observeCustomerProblems.nl` consumes the original `ObservatoryQuestion` and `SignalObservationSet` fixture contract. `assembleRequest.nl` and `assembleDossier.nl` map only supplied fields into the app's working records; the dossier adapter explicitly leaves raw-episode and exact-trend-receipt collections empty because the input does not supply them. The root then orders the domain dependencies: `extractCustomerSituations.nl` identifies episodes; `versionCustomerIdentity.nl` resolves only source-backed mappings before `deduplicateIncidentEvents.nl` distinguishes copied tickets from independent events; `versionProblemConcepts.nl` retains stable concepts and rename history; `revokeAttributionDerivatives.nl` handles consent changes; and `compareTrendCoverage.nl` gates all trend claims before `bindTrendAggregates.nl` can use exact receipts. `commissionDiscriminatingInvestigation.nl` takes the remaining mechanism questions and counterevidence.

Trend claims require comparable populations, windows, channel semantics and exposure. Exact aggregation receipts bind cohort query and source versions; no rate is inferred from complaint volume. Consent withdrawal triggers attributable quote removal and recomputation proposals while preserving non-attributable evidence. Investigation tasks target unresolved mechanisms that could change a product decision and include evidence on both sides. The public operation now accepts an `ObservatoryCheckpoint` and returns a case-bound checkpoint. A changed source snapshot appends only changed domain editions; a repeated identical snapshot is a no-op. Consent withdrawal, mapping revisions and changed event/concept groupings selectively invalidate dependent derivatives while preserving unaffected trends and investigations. The checkpoint records pending deletions and recomputations without claiming their external receipts.

Trend aggregation is explicitly null until exact comparable coverage and receipts allow the typed aggregate child to run. Checkpoint reconciliation and the public result retain that null trend value on blocked windows, so no unbound aggregate is read or fabricated.
