# Functional substitution sourcing design

The sourcing program begins from the intended use and its critical operating conditions, then derives essential properties from supported evidence. It searches for mechanism alternatives but binds every claim to the supplier, item, and revision that supplied it. Unit conversions are accepted only from exact receipts; a candidate must pass each critical property and interacting interface condition independently. Qualification criteria precede any supplier test, and a passing sample is bounded by an approved lot-level rule. Adapter cost, lead time, and interface risk enter the installed comparison. Final approval is scoped to the specific machine, environment, and revision so one permitted use does not become a general substitution.

The program returns a proposal with unknowns and residual risk, not a purchase or a completed test.

Critical unknown requirements produce a blocked `SubstitutionProgramResult` with explicit null candidate-dependent stages, all independent guardrails, and a reconciled checkpoint. The branch preserves the unresolved requirements instead of returning an untyped partial description.
