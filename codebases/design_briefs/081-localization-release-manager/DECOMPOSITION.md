# Localization Release Manager

## Context-addressed translation and versioned journey bundles

Segment identity includes content, product context and grammatical role, so identical source strings do not collapse different meanings. Concept/sense-specific terminology precedes transformation; conflicting approved forms require owner resolution. Source punctuation and glossary changes invalidate only semantically affected segments.

Every transformed segment undergoes independent meaning review and exact protected-token checks. Structural validator receipts bind to the actual source, candidate and validator versions; absent receipts block a critical release. The bundle operation checks entire user journeys and explicit fallback policy, preventing a delayed locale from mixing incompatible old and new instructions. State preserves translation, glossary, context, review and source editions independently.

## Verification boundary

The original domain records, five semantic gates, five operational scenarios, and independent finite gate answers remain the contract. Public operations and checkpoints belong to this application. Native loading and source-call inspection do not prove learned execution quality. Effect intent is distinct from an authorized receiver receipt.

The public operation constructs its complete typed carried state on every return, including blocked and no-change outcomes. Only the domain-specific observed change updates its own fields; prior receipts, unrelated history and unresolved external outcomes remain inspectable. Guardrail findings are consumed by the result or the action eligibility they govern.
