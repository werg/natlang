# Contract obligation workbench

This workbench parses duties into actor, modality, action, trigger, deadline, and exception facets pinned to an executed edition. It constructs a relation graph across duties, exceptions, dependencies, conflicts, and supersession; related clauses remain separate obligations. Each observed event is tested against each obligation's trigger facts, so partial fulfillment and ambiguous activation remain explicit. Only active, actor-identified duties become owned tasks, and completion updates remain evidence-linked rather than inferred from a notice draft. A separate identity lineage treats name changes as uncertain until assignment or succession is evidenced. Calendar-dependent deadlines use a supplied authoritative calendar resolution; notice preparation never stands in for dispatch or contractual effectiveness. Confidentiality routing redacts to the minimum supported instruction and records its purpose boundary.


## Review completion and blocked-state construction (2026-10-26)

Duty performance planning always returns a task ledger, including an empty blocked ledger when no duty is active. Absence of a saved checkpoint is a first review, not a synthetic completed contract history.
