# Apprenticeship practice simulator

The simulation treats each learner utterance as either a question or a proposed typed operation. Unscripted questions are answered from the actor's visible facts; unknown actor knowledge stays hidden. Action proposals must match the current procedure step and its prerequisites. A saved turn ID prevents a retry after a network interruption from applying the same simulated resource change twice.

World advancement checks resource and procedural invariants before replacing the prior state. Unsafe behavior is refused or handled under the approved training scenario, without invoking a real control. Challenges are selected from the objective-specific catalog using a saved seed, filtered for repeat exposure, and checked for a discoverable recovery route. Debrief traces each finding to observed action IDs and distinguishes process quality from a fortunate or adverse outcome. Session checkpoints preserve prior state, actor knowledge, and challenge lineage for a later invocation.
