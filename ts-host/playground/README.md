# Browser playground and local workbench

From `ts-host`, run `npm ci` once and then `npm run playground`. This builds the browser runtime, starts a server bound to `127.0.0.1`, and opens Chromium with the Linux WebGPU flags when available. `npm run serve:browser -- --playground` prints the URL without opening a browser. The page can also be served as static files after `npm run build`; the Jobs tab then has no local pipeline API.

## Playground layout

The file explorer opens beside the editor and selected output view. Its header collapses it to a narrow left rail, which also reopens it. The top bar selects a project, opens the example library, reveals case/training tools, and runs the current program. A compact help menu holds each example's description. Inputs, entry function, and expected value sit below the editor; output, live UI, and trace use the adjacent pane. On small screens, the panes stack.

The browser-local project last selected is restored on reload. The Projects selector lists saved workspaces, including copies opened from the gallery. The example library is searchable and filterable by category.

## Live interfaces

Two natlang examples in the gallery introduce the browser UI primitives:

- **Generated counter UI**: a loaded local model interprets `ui/view.nl` and generates a typed UI tree. A TypeScript reducer handles exact state changes. Model quality affects the generated view; the preview never substitutes a scripted model answer.
- **Generated pricing UI**: natlang generates a pricing view from typed state while a TypeScript reducer handles seat and billing events.

The TypeScript-only counter and pricing programs remain internal runtime examples for deterministic testing; they are not shown in the gallery.

A project becomes a live application when its entry is `ui/view.ts` or `ui/view.nl`, it includes `ui/reduce.ts` or `ui/reduce.nl`, and its input JSON contains a `state` object. These are portable source files, so project import/export retains the live behavior. `BrowserNatlangApplication` executes reducers and views through the browser client; `BrowserDomRenderer` projects the returned node tree. Text is rendered as text, with no generated HTML or JavaScript execution.

**Live edit** automatically applies valid TypeScript source changes after a short pause and keeps current application state. Model views run explicitly with **Apply & run**, which starts from the input state; **Reset** does the same. Natural-language examples label the Run button “Load model to run”; selecting it opens model setup and resumes the pending run after a successful load. The preview includes generated view data, state, and reducer/view traces. Each view execution is also saved as a normal run, so Result, Trace, download, forking, and case capture remain available.

The timeline retains up to 80 snapshots for the current live session. Scrubbing restores the recorded view and state, pauses its controls, and never executes a reducer or replays effects. **Back to live** restores the current interactive view. Source edits preserve prior snapshots; Reset and project switching clear this timeline. Source and view-run records persist in IndexedDB, while interactive state and the combined timeline are session-local.

## Editor and interpreter

The project selector, file tree, entry function selector, and editor work on browser-local projects stored in IndexedDB. Projects contain `.nl` and `.ts` files, inputs, and an optional expected value. Import and export use project JSON. The gallery has 14 natlang programs spanning extraction, classification, policy decisions, composed calls, and live interfaces. Opening one creates an editable copy; existing projects are left alone. The Inputs panel reads the entry function's declared argument types and presents controls for text, numbers, booleans, literal choices, and records. Lists, dictionaries, and unsupported shapes use a field-level JSON editor with type validation; the full input object is available under Edit JSON. The editor highlights source and checks the natlang graph and TypeScript syntax while keeping invalid edits editable. `Ctrl`/`Cmd`+`Enter` runs a checked revision; the Stop button requests cancellation.

The browser runs the native TypeScript interpreter through the reusable [browser client](../BROWSER_CLIENT.md). Crisp programs run without a model. Natural-language functions need a loaded GGUF checkpoint, either from the listed model catalog, a GGUF in the local `models/` directory, or a user-selected file. The model dialog reports WebGPU capability and storage headroom. Automatic loading requests full GPU offload when the adapter supports it and retries on CPU if GPU loading fails. A local GGUF made by the training pipeline appears after refreshing the Jobs catalog. The base model's quality is limited; exact expected values and case admission must still be reviewed.

Every run pins its source, inputs, revision, outcome, emitted values, and reduction trace. Runs are stored locally and can be downloaded. The Result panel compares any two runs from the same project, including outcome, value, duration, model turns, token counts, and retries. The Trace panel navigates captured events and reconstructed state without executing recorded actions or effects. Fork source creates a new editable project from the recorded revision; it does not resume execution from a trace event.

## Cases and training

Save a run as a case, or create a scenario directly from the current project. Edit its expected outcome and ordered action/effect/call obligations, then use Run case to execute its frozen source and inputs. A new observation returns the case to draft review. Accept checks the captured trace against the case contract. Cases remain browser-local until exported as JSONL or sent to the local pipeline. Import retains their source and trace. Sending accepted cases freezes a JSONL batch in `data/` with a digest and split manifest. The `cases_ir` job converts representable cases into shared `natlang.program/1` IR and writes a rejects JSONL for cases it cannot represent. Currently this adapter admits natural-language leaf functions with successful root actions and no host effects; linked child calls or richer traces are explicitly rejected. No rejected case silently becomes training gold.

The Jobs tab runs case conversion, teacher collection, SFT export, turn evaluation, training, and browser model publication. The live case importer, teacher trajectory projection, SFT exporter, and turn evaluator use Node scripts; generic `program_ir` materialization is disabled in the workbench until a Node implementation covers its schema. Requests for the retired materialize job fail closed with a Node-only migration message. A successful training job merges the checkpoint, converts it to Q4_K_M GGUF, verifies it, and publishes it as the shared browser default. The checkpoint publication job can publish an existing merged checkpoint with a selected quantization. Publication updates `models/browser-catalog.json` atomically after the weight and template files are ready. Refreshing the Jobs catalog selects the new default unless you explicitly chose another model. Select a dataset and a unique job name, then start a step. Teacher collection, SFT export, and turn evaluation use an HTTP model server on localhost; these jobs do not use the GGUF currently loaded in the browser. Evaluation results show exact counts and the frozen sample manifest hash. The checkpoint selector lists only merged checkpoint directories. Job state and logs survive page refreshes under `runs/playground-jobs/`; interrupted jobs are marked as such after a server restart. Stop requests termination of the job process group.

For a reviewed leaf case, use: send accepted cases → `cases_ir` → choose its `*-program-ir.jsonl` → `teacher` → choose the generated `*-teacher-turns.jsonl` → `export` → `train` → `evaluate` → `gguf`. The teacher step writes raw trajectories and projects them into native training turns. Generic program IR materialization is not exposed as a live job because its reference generator remains Python-backed; unsupported materialize requests are rejected. The Node importer is deterministic, while teacher collection needs a running model server and review of its output. The local job service checks origin and a per-server token, only accepts localhost requests, and restricts generated paths to `data/`, `runs/`, or `models/`. It is intended for a trusted local workstation.

## Verification and limits

Run `npm test` for TypeScript/runtime checks and example validation, `npm run test:playground` for a real browser UI smoke, and `node --test test/playground-*.test.mjs` from `ts-host/` for the Node case conversion, evaluator, and dispatch checks. Internal TypeScript fixtures are executed against their advertised results; natural-language examples are checked for valid source graphs, but their reference answers still require model evaluation and review. Set `NATLANG_CHROMIUM` if Playwright's bundled Chromium is unavailable.

The browser app shell uses deterministic JavaScript and the native natlang interpreter for user programs. The existing natlang `codebases/ide/` exercises IDE behavior in the Node workbench; the interactive shell does not yet execute a natlang `ide/step.nl` on every UI event. Source checks are syntactic and graph checks, not a proof that model actions will be correct. Recorded trace navigation cannot replay external effects or pause a live model at arbitrary events. The browser eval environment is trusted application code; do not load untrusted programs into a privileged host object.

## Extending the example library

Add gallery examples in `examples/natural.mjs` or `examples/interfaces.mjs`, and include them in `examples.mjs`. Keep deterministic TypeScript fixtures in `examples/crisp.mjs` for runtime tests. Each entry carries a stable ID, category, difficulty, short description, concepts, virtual source files, inputs, and an optional reference result. Keep all companion files in the entry so it works from static hosting and when copied into a browser-local project. `test/playground-examples.test.mjs` checks gallery metadata, loads every graph, and executes every TypeScript fixture against its reference result. Review natural examples with a local model before treating their observed runs as cases or training gold.
