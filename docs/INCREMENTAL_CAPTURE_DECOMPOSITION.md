# Incremental call evidence

Completed model replies are journaled by VibeStudio's common model adapter. Exact native results and input value blobs also need a checkpoint before an unfinished call can disappear. Keep a separately tagged running checkpoint; do not manufacture a completed call record.

Inventory: `CallCapture` in `ts-host/src/calls/recorder.ts` owns exact inputs, effect ValueRefs and their blobs. `runtime/kernel.ts` wires agent AND crisp effects. `native/effects.ts` observes asynchronous external calls and synchronous service values. The durable portable `calls/store-core.ts` and VibeStudio RecordsStore both implement the optional store checkpoint interface; caller-provided in-memory stores may omit it. Node's file/SQLite and in-page stores built on portable CallStore share its implementation. The BrowserCallStore worker protocol explicitly acknowledges checkpoint commits; it does not send a large compilation snapshot on each checkpoint. Its previously missing discard forwarder is included. Serving backends return model responses and do not interpret this call-store interface; the same recorder runs around all configured model routes. Learners/materializers consume saved artifacts and do not own these live writes.

Mechanism: checkpoint exact running state and blobs after inputs and completed effects. Await a checkpoint for an asynchronous service result before delivering that result; preserve synchronous service return types and let their enclosing runtime's next awaited operation flush queued storage. Record full metadata and the current event stream without inventing a final output, ended timestamp or graph seal. Final records atomically supersede running checkpoints. Ordinary recording remains optional; `recording.checkpoints:false` opts out. Capture-enabled VibeStudio collection requires its durable store; its asynchronous capture failure is surfaced rather than treated as task success.

This is exact data plumbing, not task policy or a prescribed route. Targeted tests verify persisted unfinished inputs/effects/blobs, process/store reopening, asynchronous result acknowledgement, unchanged synchronous return semantics and no invented completion.

Validation: targeted Node/portable-store/native-effect suites passed (78 tests), final browser protocol/portable suites passed (54), and real Chromium OPFS close/reload preserved an unfinished native receipt without a fabricated completed record. Temporary Node and browser test stores explicitly disable the production20GiB free-space eviction reserve so unrelated host disk pressure cannot erase their test fixtures. Ordinary production eviction remains configured by its existing settings; captured VibeStudio records are separately pinned. Stale progress is ignored for absent/finished calls in the shared portable store, matching the records worker.
