# Native program improvement

`folder.iterateOn(step, initialState, ...fixed)` repeatedly applies a directory reducer on a private source branch. Each successful step checkpoints source and portable JSON state together. It returns `{folder, state}`; `folder` is an immutable snapshot and the receiving folder is unchanged.

```ts
const result = await source.iterateOn(improveStep, initial, policy)
  .withMeasure(state => policy.maxExperiments - state.iteration)
  .until(state => state.done);
```

The numeric measure checks remaining work, not code quality: it must be a nonnegative safe integer and decrease strictly after every successful step. Zero remaining work without meeting the stopping predicate raises `IterationLimitError`. A nondecreasing measure rejects the step and retains the previous checkpoint. The default semantic progress judge remains active, reviewing usefulness and stopping unproductive runs early. `.checkProgress(customJudge)` replaces that semantic judge; `.checkProgress('off')` disables only semantic reviews. There is no instruction or function-entry gas.

Iteration must have a decreasing measure or a finite `withLimit({maxSteps})` bound before doing work. A satisfied initial predicate still returns in zero steps.

Within a step, use `folder.propose(rewrite, request)` to edit privately, `evaluator.check(proposal.folder)` to compile it, and `evaluator.evaluate(proposal.folder, {split: 'train'})` to execute that source in fresh workers. Validate it on the validation split. `await folder.accept(proposal)` publishes only a proposal from that folder's current revision and returns the installed immutable snapshot. The reducer's explanation remains `proposal.value`. `folder.select(snapshot)` installs the exact selected source from the same target lineage. Accepting a child of a population parent does not select that child as incumbent.

Snapshots materialize bytes and have content identities. `snapshot.branch()` opens an independent writable branch. Proposals are authentic local capabilities; copying their fields does not create another acceptable proposal. Snapshots register automatically in their folder lineage: store `snapshot.digest` in state and retrieve it with `folder.at(id)`. No source-registration service is needed. A failed step exposes the last joint source/state checkpoint through `error.lastState`.

`improveProgram` installs the authored program in `applications/program-improver`. The host supplies compilation, fresh-worker target execution, split restrictions, source storage, and shared accounting. The authored directory reducer chooses hypotheses, edits, evaluation requests, acceptance, population updates, and selection. Target workers receive only their deployment fixture services. They cannot access the improver's evaluator. Editable application modules use the compiler's constrained profile, including recursion guards and finite iteration.

`SourceEvaluator` exposes training inputs, independent expected outcomes, observed results and paged training evidence. Validation exposes scores for population selection; it keeps case outputs hidden. Its top-level `confirm` operation consumes the final test cohort once against a frozen source identity. `confirmPair` freezes both baseline and selected source, then reports their effect and an exact paired sign test. A durable journal permits resuming the same experiment after a crash and rejects a different candidate or significance retry. It is absent from the injected service surface.

The `optimize` SDK and CLI execute `componentSearchStep.nl` as their search loop. Exact helpers retain seeded frontier selection, dependency groups, three-way merges, paired minibatches, guidance coverage and protected incumbents. The source-improvement application expresses its semantic loop in `improveStep.nl`; both use the same folder iteration and model tool surface. There is no legacy scheduler switch.

The self-improvement scripts index failed and recovered actions across existing training artifacts, reconstruct source targets with disjoint groups, build bounded cases, collect actual authored trajectories, and export improver-owned exchanges. Altered historical code or prompts require replay before renewed training admission. Infrastructure, oracle issues, held-out incidents and missing reconstruction remain explicit dispositions.

The result includes a portable source manifest, file change list, independent baseline and selected validation, and a disposition distinguishing quality improvement, a checked transformation, retained baseline, and an ineligible result. Returning edited source does not activate it in the receiving checkout. A selected `improverSource` is frozen for one invocation and its identity is checked on resume.

Use `natlang improve init PROJECT --out CASE.json` to scaffold a case, supply independent expected outcomes, then run `natlang improve CASE.json --out RUN --model MODEL`. `resume RUN` and `step RUN` retain the recorded model/fixture identity; `inspect RUN` reads evidence and checkpoints, and `export RUN --out SOURCE.json` returns all selected files. `adopt RUN --into PROJECT` checks the completed independent result, transformation eligibility, base revision and compilation, recording `adoption.json`; `rollback RECORD` restores that recorded base. `recover RECORD` finishes interrupted publication if each tracked file still matches a recorded before/after value. Multi-file installation is recoverable, rather than filesystem-atomic.

`InstructionEditor` exposes compiler-resolved sites and replaces literal segments while retaining interpolation bindings. `implementBehavior`, `repairProgram` and `simplifyProgram` install specialized authored reducers into the same loop. `checkTransformation` reports each obligation and its evidence strength; unknown required checks remain unverified. `CounterexampleSuite` carries a finite oracle allowance across immutable versions. `counterexampleGuidedImprove` runs `counterexampleStep.nl`, admitting independent gold and invoking the normal authored repair with one shared allocation. `admitCounterexamples` creates a new immutable training suite using a pinned author-provided oracle and refuses protected input overlaps. `composePortfolio` installs complete member sources, an authored router and a named fallback member.

Service scope keys name services. A bare function path grants access to that call; `path/**` explicitly includes descendants. Evaluator authority is granted only to `improveStep.nl`; the semantic editor cannot evaluate. Joint source identities and independently measured quality are checked before checkpoint publication; invalid steps return the last committed pair.

The default root makes one call to authored `lifecycle.step(folder, evaluator, planExperiment, rewriteProgram, state, policy)`. Exact baseline measurement, acceptance and population installation belong to authored TypeScript helpers, rather than model-generated plumbing or a host scheduler. The two semantic reducers are `planExperiment` (return one evidenced hypothesis) and `rewriteProgram` (edit the source). Exact lifecycle code chooses the parent (seeded GEPA frontier or adaptive incumbent) and supplies complete source text, measured training feedback, opportunity classification and history directly to the planner. The editor likewise receives the existing source text; neither model needs to reconstruct or refetch known evidence. The exact lifecycle calls `experiment.test` once after the planner returns, then selects independently. The planner cannot invoke that helper or the editor from its scope; its private planning folder is discarded. A rejection returns to the outer finite iteration rather than prompting extra experiments inside the planner. Acceptance remains separate from incumbent selection. There are no extra model invocations for copying measurements or assembling selection records. Source-size and model-calls objectives require measured reductions while preserving quality. See [experiment results](LUNA_BONSAI_IMPROVEMENT_RESULTS.md).

For a stronger optimizer and a separate target model, supply independent SDK `improver` and `executor` drivers, or use CLI `--model`/`--provider`/`--server` and `--executor-model`/`--executor-provider`/`--executor-server`. `--executor-timeout-ms` configures a finite per-case allowance for a shared target server and is pinned on resume. All requests use the declared shared budget; there is no hidden 24-request optimizer ceiling.

`policy.objective: 'model-calls'` selects quality first and, at equal quality, fewer measured validation target requests. Reports include `modelCalls` only when independently measurable. Repeated evaluations of identical immutable source, cases and seed reuse the execution and its original request count; cached results do not masquerade as zero-cost executions. Use a distinct declared seed for an independent replicate. Population quality/count claims are checked before joint publication. Fewer requests does not necessarily mean fewer tokens or lower monetary cost.

Training outcomes distinguish invalid independent fixtures (`failureKind: 'fixture'`) from bounded target timeouts (`'timeout'`) and ordinary target failures (`'target'`). Fixtures must be repaired by their author; target instruction edits cannot repair them. Timeout outcomes retain training gold and diagnostic evidence without pretending an incorrect semantic answer was observed. Source, per-case deadlines and the shared server's availability all affect completion measurements.

Training feedback includes a bounded `modelTrace` of actual target actions paired with their resulting observations, plus `serviceDeclarations` derived from the public TypeScript service interfaces. Neither diagnostic surface exposes held-out outputs or service implementation bodies. The evaluator's injected declaration includes `modelCalls`, so an optimizer can use the measured cost without casts or invented metrics. Use the trace to distinguish semantic failure, unnecessary inspection, self-repair, delegation and a separate completion request. Read the service schema before rewriting instructions; a status field does not imply delivery-date fields.

The editor writes complete replacement text and returns `await bookkeeping.finish(folder, summary, preserves)`. The helper derives changed paths from the actual folder diff. Unchanged proposals are rejected experiments, regardless of the editor's claims. Use `eval {code, finish:true}` to compute and finish its fresh typed final expression or explicit return in one action. Omitting finish retains inspection/staging. Missing or invalid values and failed evals cannot finish an older staged answer. All normal terminal validation still applies. Sequential action batches also stop after a failed computation.

The authored experiment helper passes measured evidence directly through `planExperiment.bookkeeping.request(policy, hypothesis, evidence, sourceFiles)`; models never rebuild optional fields or measurement records. Eval scope follows TypeScript optional-property semantics, including absent `undefined` properties; portable published results retain their stricter validation. The injected evaluator pins comparisons to the invocation's seed, including independent publication checks. A different replicate belongs to a separately declared top-level invocation.

`scripts/self-improvement/prepare-observed-study.mjs PRIOR_STUDY OUTPUT` selects opportunities from completed current-student **training** executions. It distinguishes observed target failures from successful executions with avoidable requests and excludes invalid fixtures. It retains original split/group assignments and gold, records its selection evidence and declares a finite follow-up allowance. Historical failure labels alone do not count as current-student failures.

Failure ingestion includes native `result.json` artifacts and rejected experiment history. A valid population child that was not selected is not classified as a failed decision. The Luna/Bonsai development attempts have been indexed under `runs/luna-bonsai-improvement-20261001/incident-index`; failed proposals remain correction evidence rather than positive imitation targets.


Run the structural comparison with `node ts-host/scripts/self-improvement/structural-study.mjs OUTPUT probe`, followed by `native`, `direct`, and `confirm`, or run the entire sequence serially with `run-structural-series.mjs OUTPUT`. The harness copies the runtime, probes a hidden reference rewrite on training only, runs a direct rewrite and a three-experiment native loop, then freezes both selected sources before the single final paired confirmation. It emits raw exchanges, journals and a training-case seed. Semantic recommendation decisions stay semantic; batching and exact aggregation are legitimate structural transformations. Cases emitted by a probe are not positive SFT until native trajectories pass independent replay and admission.

The semantic interpreter is already present in a .nl call. For small visible inputs, judge them directly and let eval perform exact aggregation; a nested nl call is useful only when it adds a real subproblem. The editor instructions follow the same rule and distinguish inspection from completion. Tests exercise a real edit/check/measure/select path in three atomic model responses and verify that the declared request allocation permits more than 24 requests when the program needs them.

The planner receives the latest tested source and its public training observations after a rejection. Persist that evidence as opaque JSON loop memory, and give it a typed ExperimentFeedback shape in planning context; this keeps the root contract small. Validation feedback contains quality/request metrics only. Cost and size search continue after an initial improvement until the finite experiment allowance ends or the planner finds no further evidenced hypothesis; quality search can finish at perfect quality.


Shared language refinements now support this workflow without special optimizer semantics. Structured inputs show a bounded view of each field, so a large early source or log does not hide later task data. Cutoff markers identify the original field in scope; full values remain available. A semantic call can answer directly with its declared string or JSON value. Computation and effects use `eval {code, finish:true}` when complete. The planner therefore takes `brief:string, context:ExperimentContext, policy:ImprovementPolicy` and returns a hypothesis string, rather than a wrapper record. The editor still performs real folder effects and returns its diff-derived typed result.

Training traces pair actions with their actual outcomes, including terminal actions; model-request event boundaries prevent fast sequential actions from mixing errors. Old observations remain historical and require recollection under the current runtime. The migration script replaces obsolete optimizer templates directly and revokes stale admission; no compatibility paths remain.
