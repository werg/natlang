# Conditional eval local-type defect (before edits)

Observed on an actual compiled joint application against exact Core7091 evaluation vendor: `const handoff = await predicate(...) ? await nativeReceipt(...) : null` completes the native receipt effect, then rejects let/handoff as boolean. Core546 and7091 both reproduce; their scopeInitializerType implementations are identical. Parent Source39 remains immutable.

NativeRuntime.scopeInitializerType currently takes the first call-like prefix as the whole initializer's type. It therefore mistakes a conditional predicate, logical left operand or projected call for the final expression. NativeSession.evaluate uses that inference when retaining unannotated local bindings; annotations remain authoritative. The ordinary compiler's TypeScript checks already accept the expression; this is a subsequent runtime binding mismatch.

Shared producer/consumers: ts-host/src/native/runtime.ts NativeSession.evaluate/scopeInitializerType; scope-compiler.ts captures exact initializer text. NodeNativeRuntime extends the portable NativeRuntime; core Workerd/browser platforms instantiate the same interpreter. All staged SDK targets inherit it. Managed llama and in-page wllama supply generation/scoring via TS backends, Python native serve and SGLang actor supply model HTTP protocol; none parses or assigns JavaScript eval local types (docs/ENGINE_PARITY.md engine table). No server/tokenizer/model/admission/retry changes are needed. Tests must exercise Node and Workerd platforms, true/false/null results, actual native receipt fields and incorrect declared/returned types without invoking a paid backend.

Fix the expression boundary rather than splitting model code into a workaround. Recognize a complete direct call via the existing TypeScript AST; infer conditional result from its branch types when both are known, never from its predicate. Other compound expressions retain their normal actual-value inference. No new global AST cache or user-source retention. Explicit local type annotations are the existing opt-out from automatic inference.

Concrete platform citations: NodeNativeRuntime extends the portable NativeRuntime (ts-host/src/node-runtime.ts:4,31); the shared kernel instantiates it for platform execution (ts-host/src/runtime/kernel.ts:867), used by core/workerd.ts and the browser platform. Backend-only exclusions are ts-host/src/model/llama-runtime.ts (model generation/scoring), browser/local-model.ts:354 (wllama decision score requests), and serve/sglang_actor.py:1018 (model request generation); Python serve/native_protocol.py handles the model protocol. These components do not assign eval locals; changing the shared interpreter reaches their TS-host consumers without changing engine protocols.

Validation: official build:node passed on the exact source, then 19 Node/Workerd and existing field-guard controls passed in natlang-conditional-scope-type-20261125c (about1GiB peak,12.4s). Tests cover true/false/null branches, false/zero fallbacks, all falsey receipt fields, cross-eval nullable binding, projections/logical operands, wrong actual callee results and explicit incompatible annotations. Runtime annotations validate after evaluating the expression; the test correctly preserves that already-completed native effect rather than asserting rollback or an unimplemented preflight. First build lacked the new worktree's root node_modules link; restored exact existing dependencies (package/lock unchanged), no install/download. This is not a live model or physical Workerd isolate test. Official five SDK staging/reproduction and the original joint-program replay follow from the clean source commit.
