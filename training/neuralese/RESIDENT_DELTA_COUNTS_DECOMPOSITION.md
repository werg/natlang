# Delta preparation after a drained recipe handoff

The admission policy is unchanged: retain every old row and held group, admit only an authenticated append within qualified geometry, and grant no exposure during CPU preparation.

Crisp count verification uses the committed generation when one exists. Otherwise it uses the initial count only when that initial record binds the actual plan. A later SHA-bound plan may preserve an older initial as historical evidence; then the already authenticated cache-only train and held indexes provide the actual prior counts. The old initial is never rewritten, same-plan count corruption remains fatal, and the request records both plan identities and its count authority. No raw parse or model load is added.
