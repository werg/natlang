# Shared readiness with an external RAW owner

The production recipe retains the policy: finish genuine communication foundation and runtime/task execution, then begin joint semantic adaptation as soon as two models qualify. A separately supervised whole-recipe RAW controller may already own useful training.

1. Read the declared `manage_raw_bootstrap` boolean (default true).
2. Always verify the same bound RAW release, participant readiness and paired train/held data.
3. When management is false, wait for the external owner rather than launching another RAW child.
4. Once two participants qualify, use the existing semantic launch, resumable completion and subsequent joint training path unchanged.

The boolean is an explicit scheduling declaration; crisp code only enforces this ownership boundary, validates types, and preserves existing atomic state and release verifiers. It grants no readiness, stage completion or exposure. There is one shared controller for both architectures.
