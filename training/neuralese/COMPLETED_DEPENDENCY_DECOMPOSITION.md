# Completed-parent replay dependencies

Policy: preserve the genuine completed boundary and all inputs required to replay
its verifier and execute its selected continuation. Historical source provenance
remains in authenticated documents; it does not demand discarded teacher captures,
mutable past resident pointers, or original upstream preference archives.

1. Replay the existing completed verifier unchanged. Its failure still blocks use.
2. Bind its explicit proof, consumption, immutable snapshots, operation config/state,
   receipt, recipe-plan, lineage, withdrawal, and scheduling authority inputs.
3. Resolve old and future recipes with the existing inherited recipe resolver and
   normal stage-input dependency collectors. Bind those returned files without
   interpreting arbitrary JSON contents as more dependencies.
4. Bind both complete package inventories. Preserve selected external publisher,
   controller, loader, module and authority sources through their typed loader
   schemas. Select the explicit future global plan, or the old plan when it is
   also the future authority; superseded old publisher sources are historical. No source code executes during enumeration.
5. Let the existing provider continuation collector enumerate current execution
   inputs. Never replay a historical learner/checkpoint merely to enumerate files.

These are crisp exact artifact checks, not a new training/admission policy. No
weights, optimizer, RNG, exposure, intrinsic parser policy or model text changes.
