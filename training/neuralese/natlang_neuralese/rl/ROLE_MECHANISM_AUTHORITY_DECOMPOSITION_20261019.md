# Source-host mechanism authority

Policy: exchange genuine communication-ready checkpoints across explicitly reviewed runtime versions. Keep students training until real readiness and ownership release; a different approved checker implementation does not itself grant readiness.

1. The deployment plan names every role, its source host, and its exact verification mechanism hashes. This is a natural-language deployment decision represented as immutable plan data.
2. Crisp ownership validation requires either the complete six-file map for every role or the existing legacy exact-local behavior for every role. No wildcards or partial maps.
3. A publishing host compares its actual mechanism bytes to its own declared map before eligibility, release or pending publication.
4. A receiving host checks the source role's attested mechanism against that role's declared map, while retaining every existing checkpoint, communication cohort, exposure, task, numerical and release validator.
5. The full role assignments, including mechanism maps, remain part of the shared contract. A changed or omitted authority cannot import an earlier proof.

This extends the existing role exchange verifier rather than introducing a second release protocol. Hash comparisons, durable objects and ownership checks are crisp exact mechanisms. It changes no model-facing text or numerical computation.

External control overlays retain their installed module origin for runtime defaults. The mechanism inventory therefore reads an explicitly bound external control source when present, checking its path, digest and byte count; malformed or changed bindings fail closed. Installed bytes remain the authority for modules without an external source declaration.
