# Supervised stage boundary continuation

Policy: keep useful supervised work moving on the latest explicitly declared operational recipe. Preserve every source, held split, objective, optimizer/exposure debt and readiness requirement. A live worker keeps its sealed command; only the next unsealed stage takes a successor. Source additions use the exact normal no-publish resident preparation request, including unchanged-prefix/held and geometry checks, without inventing visits.

1. A fixed role-owned continuation pointer (or the live plan declaration) selects an immutable successor. The pointer is only a selector, so future recipes do not require rewriting the sealed global plan. The owner supplies an immutable successor naming its exact predecessor recipe, unchanged Python package inventory, successor recipe and optional publication selection.
2. At each unsealed supervised boundary, read the current owned model declaration again. Check the predecessor and allow only declared operational parameters; preserve every input, objective, stage and numeric execution setting.
3. Build a fresh resident metadata plan for the next worker using the same data and inherited recipe lineage. Its initial owner record is created by the actual next learner. This does not reset checkpoint exposure or create a training visit.
4. Commit the exact config/cursor transition with a durable intent under the existing production lease. Recovery finishes only that same intent and authenticates it before bootstrap reuse.
5. Recompute the next stage from the resulting recipe. Never alter an already sealed worker request, grant readiness, or acknowledge unfinished stages.

Crisp helpers perform byte bindings, exact comparisons, leases and atomic writes. The choice to submit a successor remains the existing adaptive supervisor policy; this mechanism does not invent or select new training data or objectives.

A fixed selector may also be explicitly installed in the authenticated role config, preserving an already sealed bootstrap-plan identity. Installing that selector is an owner-controlled metadata transition; the pointer grants no training credit. Restart first authenticates and consumes any existing sealed bridge request and its original config. It never reconstructs that request from the operation's advanced state; only after the earned cursor advances may the next stage apply a successor.

A successor may bind a built task-runtime directory and its existing canonical runtime inventory digest. Verify that exact inventory and every effective task-evaluation runtime before changing the RAW collector runtime in the same durable boundary intent. Python trainer/package and publication runtime identities remain separately bound. Recovery rechecks the same task-runtime identity before completing or accepting the commit; no model execution, task success, or training credit is invented.
# Recovered owned work and operation identity

When the supervisor retains the entire pending schedule after an external
optimizer continuation, reserve an unused attempt directory in the existing
cycle. This crisp durability rule prevents an older completed bridge result
from replacing the newer saved parent. Keep all old operation evidence and
checkpoint exposure; changing the work namespace grants no training credit.
