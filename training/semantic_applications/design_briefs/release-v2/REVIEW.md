# PR 4: application source review

## Result and qualification boundary

The review replaces shared semantic scaffolding with application-owned operations,
typed intermediate judgments, persistent domain state and evidence-based follow-up.
It also repairs concrete callable-scope, child-result, blocked-return and runtime
recovery defects. The corpus contains 100 independently authored application
sources; the optional HTTP and persistence host supplies exact mechanisms outside
their model-visible source packages.

[readiness.json](readiness.json) is the final machine-readable summary. It binds
the compiler, packet, fixture, architecture, type-pruning and test evidence in
this directory. This is a source and engineering review. It does not establish
learned-model task quality, live external delivery, production deployment or
training admission. Generation remains paused and `training_admission` remains
false. No teacher trajectories, student rollouts or optimizer updates were
produced by this review.

## What was wrong and what changed

### Shared semantic infrastructure prescribed too much

The earlier host made unrelated programs participate in one proposal, separate
reviewer approval and commit lifecycle. That imposed policy through the host and
encouraged the same request, stage and result concepts across unrelated domains.
The current host invokes each declared operation with its actual named arguments
and native return type. Each program chooses its own state representation,
operational decisions and recovery behavior.

Shared code now owns mechanical custody: scoped capabilities, exact JSON
validation, source identity, snapshot versions, durable invocation receipts,
transactional checkpoint and outbox writes, idempotency, cancellation and delivery
receipt validation. The host does not decide a domain approval, choose an action,
infer a successful physical outcome or reinterpret an application checkpoint.
The four shipped effect adapters only map their own closed effect kinds to fixed
topics and serialize the checked intention. Unknown kinds fail explicitly.

Every application now has an explicit state binding. A binding can target a
top-level parameter or a nested state field without overwriting the incoming
event or evidence. The stored result must fit every operation that shares its
state key. The different programs do not share one checkpoint schema.

### Semantic work needed actual callable trees

Parents now consume typed child findings for authority, applicability, evidence
lineage, conflict resolution, dependency effects and domain recovery. Complete
returns cover blocked, partial, replayed and successful paths. A blocked child
does not disappear when the parent assembles its packet, and a planned action
does not become a completed action merely because a record was created.

The final audit found two integration failures that declaration-only checks had
missed. The culinary scaling child and persistent-world effect child named exact
TypeScript functions without using their actual native exports. The scheduler
placed its frontier function one directory too deep: its caller saw a namespace,
not the intended function. The bindings and paths are corrected. The source
checker now distinguishes direct callables, namespaces, default exports and
qualified named exports, checks explicit positional arity, and follows qualified
native child identities in the potential-call graph. Real-source scripted
runtime tests exercise the exact kitchen and world-action bridges.

The research scheduler now reaches its full frontier, interval-option,
feasibility and conflict reasoning tree. It retains a deferred alternative even
when an immediate feasible assignment exists, so later constraints can still
change the chosen schedule. A deferred feasible experiment is reported as
unscheduled, rather than falsely classified as infeasible. Only exact interval
comparison remains in TypeScript.

The apprenticeship operation now returns its child's actual utterance
classification. Questions resolve only the actor's visible facts and leave the
world checkpoint unchanged; ambiguity requests clarification. Only an action
proposal enters the simulator's procedure and transition path. The native wiring
regression uses the original operational fixture without changing its truth.
Procedure-level clarification also returns before advancement. A complete
per-turn receipt preserves the action, transition, challenge and debrief for
replay without rescheduling or rewinding newer checkpoint history. Changed input
under an existing turn ID conflicts; a legacy applied ID without its receipt
stays unresolved. The debrief receives the actual typed action separately from
the simulator's transition and previously observed learner actions.

### A useful analysis was not a complete application

The review adds or repairs the domain's next operation, carried history and
observed-outcome boundary instead of treating an analysis packet as completion.
Examples illustrate different operational structures:

| Application | Native operational structure and evidence boundary |
| --- | --- |
| Decision ledger | Reopen supported premise regions, retain pending owner questions and reconcile the signed response against its exact question and revision. |
| Disclosure workspace | Carry actual sanitization receipts, plan, recipient authority and challenged spans into release decisions; withheld artifacts stay out of the returned deliverable list. |
| Cross-study harmonizer | Retain edition-specific slices and invalidations; a stale slice remains historical evidence without being returned as current. |
| Research coordination | Search and compare alternative protocol schedules, reconcile reservation receipts and recheck current day-of readiness. |
| Apprenticeship simulator | Separate information requests, ambiguous intent and simulated actions; question answering does not advance world state. |
| Repair cooperative | Record completed task IDs only from authorized, verified work receipts, never from the planned step list. |
| Building handover | Reconcile certificate obligations, correct equipment/manual variants and receiver-specific deliverables before closing handover gaps. |
| Facility complaints | Use recurrence and report-mechanism judgments to form a visit or work order, then reconcile actual field findings. |
| Referral packet | Track packet completeness and recipient transfer evidence; a transport acknowledgment does not establish accepted care or a completed handoff. |
| Serial fiction | Maintain scene-specific knowledge exposure and continuity dependencies; carry blocking findings into the complete revision dossier. |
| Documentary assembly | Reconcile cut implications, consent and corrections, then track delivery and readback for the exact assembly revision. |
| Culinary development | Scale the actual composed dishes with exact integer arithmetic, retain supplied and recomputed quantities, and let Natlang judge production implications and controls. |
| Escape-room foundry | Explore puzzle prerequisites and failure states in Natlang, check egress, compare supplied proof only as corroboration and require actual reset readback. |
| Live-event direction | Rebuild disruption dependencies while retaining distinct event and run-sheet revisions and separate reserve, acknowledge and publish effects. |
| Persistent-world game | Keep action lifecycle choices in Natlang; retain pending full action payloads and original world/rules bindings until matching receipts and readbacks arrive. |
| Negotiation arena | Use separate authority, private-fact and timing judgments, preserve ambiguity as a hold and return a complete arena result. |

These examples are source obligations, not claims that an external service or
physical workflow was deployed. Their public operations and complete source
paths are enumerated in the [application index](../../../../codebases/design_briefs/INDEX.md).

### Retired scaffolding obscured the current programs

Unused type aliases were removed by exact identifier reachability from packaged
source, while preserving the original domain contracts and exact platform value
types. The per-application declarations and hashes are retained in
[type-pruning.json](type-pruning.json). This includes inherited run, stage and
draft abstractions that no longer belong to the active application.

Unlisted source files were not deleted merely because they were absent from a
manifest. The cleanup checked their callers, concrete replacements and byte
identity where applicable. Five shallow Natlang files were exact duplicates of
their active nested children. Retired scheduler and kitchen implementations were
replaced by the reviewed active sources. Inactive qualification leaves in
applications 034–038 and 040 were removed only after checking their original
invariants against active domain owners; each application's original exact
fixture root remains. The decompositions record those ownership mappings.

The final potential-call audit reports any remaining unreferenced source, public
operations, state bindings, source sizes and maximum reachable native depth.
Repeated topologies remain visible as review prompts. A different function name,
a deeper directory or a unique structural fingerprint cannot establish semantic
diversity. The source review focuses on different domain representations,
decisions, histories and recovery behavior rather than manufacturing a unique
node count for every program.

## Runtime recovery and durable effects

The optional host now validates and commits a checked result, state update,
invocation receipt and decided outbox entries in one transaction. A stale
snapshot cannot publish a late result. An identical durable invocation replays
its stored result before inference; changed input or actor identity conflicts.
An existing effect identity reuses its durable status, while changed content
under that identity aborts the transaction. A declared nonempty effect array
cannot silently disappear when an adapter is missing.

Coalesced identical in-flight requests retain separate waiter cancellation.
Cancelling one waiter does not cancel other clients. Cancelling the last waiter
aborts the execution, rejects a late commit and releases the key for a retry.
Unknown external delivery remains unknown until matching evidence establishes
what happened. Operator reconciliation is recorded as asserted evidence; it is
not represented as cryptographic proof from the receiver.

The full repository run also exposed two runtime defects outside the application
sources. Worker startup copied process flags that Node would reject as explicit
worker options. The worker now uses the supported inherited options and an ESM
bootstrap, with a subprocess regression. Terminal EOF handling now drains
buffered input without prompting a closed readline interface; its piped-input
regression covers both queued actions.

## Independent truth and evaluation limits

The fixture audit compares this release with original PR commit
`5648b99b73d3b94af382f9e480dd2fe46915e66e`. It checks all 800 case identities,
independent expectations and oracles, exact gate inputs, original domain/source
records and original scalar evidence. The explicit retirement of legacy wrapper
metadata is recorded per case. It is not an exception allowing source facts or
expected answers to change. All 300 exact gates and 500 independently judged
workflows retain their original truth. The whole-application split stays
60 TRAIN, 20 development and 20 held-out evaluation.

The package still retains all 600 original domain records, 3,032 fields and 500
original operational requirements. The source compiler, callable checker, native
loader, typed fixture checks, state compatibility checks and source ownership
checks are separate evidence from learned execution. The exact helper and host
tests use controlled engineering drivers; no scripted answer is admitted as a
teacher trajectory or used to change fixture expectations.

The complete command outcomes and counts are in [validation.txt](validation.txt)
and [readiness.json](readiness.json). The Python portion of the repository gate
cannot run in this workspace because no available interpreter has the required
pytest, PyTorch and Transformers APIs. That failure remains explicit; the full
gate is not described as green. It needs the repository's compatible Python
environment before merge qualification. The TypeScript results are reported
separately and do not clear that missing gate.

Before training or production admission, the approved self-hosted teacher must
execute the frozen programs in an authorized generation window, and independent
review must inspect actual full trajectories, branch outcomes, interruptions,
state restoration, evidence corrections and delivery reconciliation. External
adapters need their actual configured receivers and production readback tests.
The existing [model-facing debt register](../../../../plans/MODEL_FACING_CHANGES.md)
records these obligations. No live or production qualification is inferred from
source depth, test counts or a clean compiler report.

## Reproducing the source evidence

From the repository root, after installing the repository dependencies:

```sh
node ts-host/scripts/design-briefs/check.mjs --report /path/to/compiler-check.json
node ts-host/scripts/design-briefs/build.mjs --out /path/to/packet
node ts-host/scripts/design-briefs/audit.mjs \
  --baseline 5648b99b73d3b94af382f9e480dd2fe46915e66e \
  --packet /path/to/packet --out /path/to/audit
scripts/check-main.sh --quick
scripts/check-main.sh
```

The packet manifest records the source-only JSONL file hashes. Large generated
packet files are rebuilt from the repository sources rather than duplicated in
this release directory. The historical release-v1 evidence remains unchanged.
